# 0018. スライドはHTMLだけで納品し、PowerPoint変換をやめる

## コンテキストと問題

`digital-agency-slides` は、デッキをHTMLで作り、同梱のツールで編集可能な PowerPoint(.pptx)に変換するスキルとして追加された。変換を成立させるため、作成面のほうを PowerPoint が表せるものに合わせて固定していた。

- 1 CSS px = 0.75 pt = 9525 EMU の換算を不変条件とし、拡大縮小を禁じた。
- `::before`・`::after` に描いた装飾は変換で失われるため使えなかった。DADSの見出しコンポーネントのチップ(縦線)のように、公式コンポーネント自身が擬似要素を使うものも、公開どおりには使えなかった。
- 見出しを `sld-message` と `sld-eyebrow` として再実装し、DADSの見出しコンポーネントを使っていなかった。
- `data-pptx` 属性、`python-pptx` への依存、変換用の中間表現と検査が必要だった。

利用者は、変換を一度も使っていないことを確認した。デッキはHTMLのまま提示・配布されている。変換のための制約は、何も得られないまま、HTMLとしてのDADS準拠を妨げていた。

あわせて、スライド1枚の内容を短くする指針(1枚1主張、詰まったら分割する)が枚数を増やし、聞き手が全体を追えなくなる問題が報告された。

## 決定要因

- 成果物はHTMLであり、提示・配布もHTML(または印刷したPDF)で行われる。
- DADSの公式コンポーネントを、公開どおりのマークアップで使えること。
- 枚数の上限が、内容の構造から導けること。
- DADSへの準拠を機械的に確かめる手段を残すこと。

## 検討した選択肢

1. **現状維持**: 変換を残す。使われない機能のために制約を払い続ける。
2. **変換を任意の機能として残す**: 制約を「変換するときだけ」に弱める。作成面に二つの規約が並び、どちらで書かれたデッキか分からなくなる。
3. **変換を削除し、HTMLだけを成果物とする**(採用)

## 決定

選択肢3を採る。

- `deck.py` は `lint` と `preview` だけを持つ。`pptx` と `ir` のサブコマンド、`python-pptx` への依存、変換の参照文書、`data-pptx` 属性を削除する。
- 変換用の中間表現を作っていた `extract_slides.js` を、所見だけを返す `check_slides.js` に置き換える。文書の検査(`lang`、`<title>`、`h1` が1つ、見出しレベルを飛ばさない)を加え、変換のための検査(擬似要素の装飾、変換できない要素、スライドの `transform`)を除く。
- 見出しはDADSの見出しコンポーネント(`hgroup.dads-heading` とショルダー)、用語の定義は説明リスト、出典はリンク、状態はチップラベルを、公開どおりに使う。`sld-*` はスライドの寸法と、DADSが公開していない静的なブロックに限る。
- 表紙は白地とし、DADSの見出しの色を上書きしない。

構成の指針は、同じ変更で「前提 → 結論 → 論点の木」に改める。スライドを木の節(主張とその直接の子)に対応させ、根拠を独立したスライドにしない。本編は論点の数 k に対して k + 4 枚以内とし、`lint` は本編が既定9枚を超えたとき(`deck-long`)、結論スライドが3枚目より後のとき(`late-answer`)、付録の後に本編が続くとき(`appendix-order`)に警告する。区切りスライドと目次スライドは廃止し、結論スライドの木が目次を兼ねる。

### 影響

- 既存のHTMLデッキで `data-pptx="raster"` や `data-pptx="notes"` を使っていたものは、属性が無視されるだけで表示は変わらない。発表者メモは `.sld-notes` で引き続き非表示になる。
- 旧テンプレートの `sld-message`・`sld-eyebrow`・`sld-rule`・`sld-on-accent` と、濃色の表紙・区切りスライドの規則は `slide.css` から消える。旧テンプレートから作ったデッキは、旧 `slide.css` を持ち続ければそのまま表示できる。
- PowerPoint が必要になった場合は、このスキルの対象外となる。

## 確認方法

- `bash tests/run-digital-agency-slides-skill.sh` — 変換の痕跡が無いこと、テンプレートがDADSの見出し・説明リストを使うこと、fixture に対する所見のコード、取得した公式資材でテンプレートの所見が0件で本編7枚・結論が3枚目であること。
- `preview` の画像を目で確認する。
