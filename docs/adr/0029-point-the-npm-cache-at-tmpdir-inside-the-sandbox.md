# 0029. サンドボックスの中の npm のキャッシュを `$TMPDIR` に向け、`~/.npm` は開けない

## コンテキストと問題

サンドボックスの中で `cdk synth` を実行すると、`~/.npm` への書き込みが拒否された(利用者の報告、2026-11-18)。サンドボックスが書き込みを許すのは `~/.npm/_logs` だけである。`~/.npm` には `_cacache`(パッケージのキャッシュ)、`_npx`、`_logs` がある。拒否された書き込み先は、`_cacache` か `_npx` と推測しており、拒否メッセージの全文では確かめていない。

`_cacache` と `_npx` は、サンドボックスの外で動く `npm` と `npx` が再利用する。中のコマンドがここに書けると、細工したパッケージを置いて外で実行させる経路ができる。`~/.npmrc`(認証トークンを置くことがあるファイル)は `~/.npm` の外にあり、この判断の対象ではない。

## 決定

`~/.npm` は開けない。npm を使うコマンドには、そのコマンドの前に `npm_config_cache=$TMPDIR/npm-cache` を付けて、キャッシュを一時ディレクトリに置く。この指示は、`npm` が入っているセッションの `SessionStart` フックの注意に足す。`harness/settings.json` の `sandbox` の設定は変えない。利用者の選択(2026-11-18)。

### 結果

- 良い点: 設定の許可範囲が増えず、キャッシュ汚染の経路もできない。
- 悪い点: キャッシュがコマンドごとに空から始まるので、初回の取得が遅くなる。
- 悪い点: 注意は Claude への指示であり、強制ではない。前置を忘れたコマンドは、拒否されて失敗する。
- 悪い点: 拒否された書き込み先が `~/.npm` 以外の場合は、この対処では直らない。
- 未確認: `npm_config_cache` の前置で `cdk synth` が実際に通ること。このリポジトリには CDK のプロジェクトがない。

## 検討した選択肢

- **キャッシュ先を `$TMPDIR` に向ける(採用)**: 上記のとおり。
- **`~/.npm/_cacache` だけを `allowWrite` に足す**: 速くなる。代わりに、キャッシュ汚染のリスクを受け入れる。`SBX-09` の期待値と ADR の更新も要る。利用者は見送った。
- **`~/.npm` 全体を開ける**: 設定は最も単純。代わりに、`_npx` も書けるようになり、外で動く `npx` への経路が広がる。
