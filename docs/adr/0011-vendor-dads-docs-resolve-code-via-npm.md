# 0011. DADS公式資料はドキュメントをvendorし、コードはnpmで解決する

## コンテキストと問題

`digital-agency-frontend` スキルは、デジタル庁デザインシステム（DADS）の公式資料を
どこから取得するかという方針を、spec 015 の時点で「外部URLを参照する手書きの要約を
1ファイル持つ」と定めた。同 spec の `research.md` は「Markdownアーカイブを追加しない」
ことを明示的に決めている。

その方針は運用に耐えなかった。要約ファイルは取得日 `2026-07-20` とDADS版 `v2.16.0` を
本文に固定していたが、公式サイトは既に `v2.17.1` に進んでおり、記録された版は事実と
食い違っていた。版を本文に書き込む設計そのものが、陳腐化を構造的に生む。

一方で前提が2つ変わった。

- デジタル庁が、サイト全文を**AI参照用途向けに**Markdown化した公式アーカイブを配布
  するようになった。125ファイル・約1MBで、設計意図・コンポーネント仕様・
  アクセシビリティ方針を含むが、コードは実質的に含まない。
- 公式Reactサンプルが npm パッケージ
  `@digital-go-jp/design-system-example-components-react` として公開された。
  併せて `@digital-go-jp/tailwind-theme-plugin` と `@digital-go-jp/design-tokens` も
  公開されている。コードは「コピーする対象」ではなくなった。

同時に、エージェントがDADSのTailwindトークン名（`text-std-17N-170`、`bg-key-900`、
`rounded-8`、`desktop:`）を推測で書くと確実に誤るという実装上の問題が残る。手元に
参照可能な語彙がなければ、この誤りは防げない。

決めるべきは、公式資料の取得方針を、文書とコードで分けて定義することである。

## 決定要因

- 常に最新版を使用できること。版を文書本文に固定する設計を排除する。
- 公式側が更新されたとき、取り込みコストが最小であること。
- トークン名など、推測が必ず失敗する情報は手元で参照できること。
- 文書（出典表記が必要）とコード（MIT、改変利用は出典不要）でライセンスが異なり、
  同じ扱いにできないこと。
- npm公開により、コードを複製する技術的必要が消えたこと。

## 検討した選択肢

- アーカイブを取り込まず、外部パスと公式URLを参照するだけにする。
- アーカイブ本体は持たず、コンポーネント名→公式URLの索引のみを持つ。
- 3つの公式リポジトリ（React・HTML・テーマプラグイン、計約8MB）を丸ごとvendorする。
- **文書アーカイブを逐語コピーでvendorし、コードはnpmと公式リポジトリから
  実行時に解決する。**（採用）

## 決定

DADS Markdownアーカイブを `.claude/skills/digital-agency-frontend/references/dads-docs/`
に**逐語コピー**で取り込む。ファイルは一切改変せず、スキル側の解説文はアーカイブの
文言を複製しない。これにより更新は「ディレクトリを削除して置き直す」だけで完了し、
周辺ドキュメントの書き換えを伴わない。版はアーカイブ自身の `index.md` から読む。

公式コードはvendorしない。実装は npm パッケージへの依存として導入し、版は
`npm view` で実行時に解決する。スキルが保持するのはトークン語彙とDADS固有の
実装イディオム（`aria-disabled`、フォーカスインジケーターの固定レシピ、44pxターゲット、
`forced-colors` 対応）の蒸留であり、これらは公式リポジトリの `AGENTS.md` および
`.agents/skills/component-rules/SKILL.md` に準拠する。

版番号・取得日を本文に固定することを禁止する。

### 影響

- Positive: 公式アーカイブがオフラインでgrep可能になり、コンポーネント仕様と
  アクセシビリティ方針を推測せずに参照できる。`MANIFEST.md` が日本語名→パスの
  索引としてそのまま機能する。
- Positive: アーカイブ更新が置き換えだけで済み、スキル文書の同時改訂を要さない。
- Positive: コードが公式の更新に自動追従し、複製に伴う陳腐化を負わない。
- Positive: 文書とコードでライセンス上の扱いを分離でき、出典表記の要否を正しく
  区別できる。
- Negative: リポジトリが約1MB増える。
- Negative: アーカイブは配布時点のスナップショットであり、公式サイトより古くなる。
  情報源の優先順位（ライブ > インストール済みパッケージ > アーカイブ）を運用で
  守る必要がある。
- Negative: 蒸留したトークン語彙もスナップショットであり、テーマプラグインの更新と
  乖離しうる。インストール済みパッケージを権威とする運用に依存する。
- Negative: spec 015 の「Markdownアーカイブを追加しない」という記録を覆すため、
  計画履歴と現状が一致しなくなる（履歴は追記型の記録として保持する）。

## 確認方法

`tests/run-digital-agency-frontend-skill.sh` で検証する。

- `SRC-09` — スキル本文および全リファレンスがDADS版番号を固定していないこと。
  本決定の中核であり、退行を直接検出する。
- `ARCH-01`〜`ARCH-08` — アーカイブが存在し、Markdownのみで構成され（逐語コピーの
  維持）、自身の版と `source_url` を保持していること。
- `IMPL-05` — 実装リファレンスが `npm view` により実行時に版を解決すること。
- `SRC-03`、`SRC-04` — 更新手順と、アーカイブから版を読む手順が記載されていること。
