# 0019. スライドの枚数は論点の木に従わせ、上限を既定にしない

## コンテキストと問題

[ADR-0018](0018-html-only-slide-decks.md) は、スライドが増えて聞き手が全体を追えなくなる問題への対処として、本編を論点の数 k に対して k + 4 枚以内とし、`lint` が既定9枚を超えた本編を `deck-long` として警告するようにした。同じ変更で、各スライドの右上に資料の構成と現在の部分を示すトラッカー、見出し上のショルダー、`n / N` のページ番号を置いた。

利用者から、構成はミント・ピラミッドに従っていればよく、全体のどこにいるかが分かるなら枚数は厳密でなくてよい、という指示があった。k + 4 の上限のもとでは、根拠そのものが主張であり固有の根拠を持つ論点(論点の下にもう一段の木がある論点)を、1枚に詰め込むか付録に送るしかなかった。前者は1枚の密度を上げ、後者は本編の論証を欠けさせる。

ADR-0018 が上限を設けた理由は「聞き手が全体を追えなくなる」ことであり、枚数そのものではない。現在地の表示はその問題を枚数とは独立に解決している。

## 決定要因

- 構成はミント・ピラミッド(論点の木)に従うこと。
- どのスライドでも、資料全体のどこにいるかが分かること。
- 1枚は木の1つの節とその直接の子だけを持ち、節を分割しないこと(ADR-0018 の方針を保つ)。
- 場の都合で枚数に上限がある場合は、それを機械的に確かめられること。

## 検討した選択肢

1. **現状維持**: k + 4 の上限を既定のまま残す。下にもう一段の木を持つ論点を表せない。
2. **上限の既定値を上げる**: 数字を変えるだけで、木の形と枚数の不一致は残る。
3. **枚数を木に従わせ、上限は任意にする**(採用)

## 決定

選択肢3を採る。

- 本編の枚数は木が決める。表紙、前提、結論、論点ごとに1枚、継続スライドごとに1枚、依頼。
- 根拠が主張であり固有の根拠を持つときに限り、その根拠を論点のスライドの後に独立したスライドとして置く。`data-layout="point"` に `data-continues` を付け、ショルダーを `論点n-m` とする。継続スライドも節とその直接の子だけを持つので、節の分割ではない。
- トラッカーはスライドではなく部分を並べる。継続スライドは、続けている論点と同じ部分を現在として示す。`lint` はこの対応を検査し、誤りを `tracker` エラーとして報告する。
- `deck.py lint` の `--max-slides` は既定値を持たない。指定したときだけ `deck-long` を警告する。
- 目次スライドと区切りスライドは引き続き置かない。結論スライドの木が目次を兼ねる。

あわせて、テンプレートに公式のノティフィケーションバナー(継続スライドの留意事項)とブロッククオート(付録の原文引用)を加えた。バナーの閉じるボタンとアクションボタンは、スライドでは操作できないため除く。

### 影響

- 既存のデッキは変更なしで `lint` を通る。ただし、9枚を超える本編に出ていた `deck-long` の警告は、`--max-slides 9` を指定しない限り出なくなる。
- 継続スライドを使うデッキでは、トラッカーの項目数が本編のスライド数より少なくなる。

## 確認方法

- `bash tests/run-digital-agency-slides-skill.sh` — 既定で上限が無いこと(UNIT-03)、`--max-slides` を指定したときだけ `deck-long` が出ること(LINT-04, LINT-04b)、継続スライドが論点と同じ部分を示し、誤った部分を示す継続スライドだけが報告されること(LINT-17)、取得した公式資材でテンプレートの所見が0件で本編8枚・結論が3枚目であること(E2E-02, E2E-03)。
- `preview` の画像で、継続スライドのトラッカーが論点の部分を示していることを目で確認する。
