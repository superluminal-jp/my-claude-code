# Documentation Integrity

ドキュメントはパブリックコントラクト（公開契約）の一部である。正確で、正典（canonical）であり、それが真である範囲の近くに置かれ、説明対象の振る舞いと同期していなければならない。

## Contract synchronization

- 変更されたすべての公開インターフェース——エクスポートされたAPI、コマンドオプション、設定フィールド、スキーマ、あるいはユーザーに見える振る舞い——について、それを説明している既存のアーティファクトを特定し、同じ変更の中でそのアーティファクトを更新すること。
- 変更されたコントラクトが既存の説明を陳腐化させた場合、ドリフト違反としてフラグを立てる。陳腐化したアーティファクトを名指しし、それが同期されるか、理由付きのオーバーライドが記録されるまで、変更完了として報告しないこと。
- フォーマット変更、非公開な名称変更、あるいは公開コントラクトを変えない内部リファクタリングについては、ドキュメントの手直しを要求しないこと。
- 独立した意思決定記録（decision record）、オンボーディングガイド、設計ドキュメントは、単にコードとは別に作成されたというだけの理由でコントラクトドリフトとはみなさない。

## Canonical source by scope

事実は、それが真であると言える最小の安定したスコープに置く。

1. リポジトリ全体に関わる事実はリポジトリの紹介に；
2. サブシステムやディレクトリに関わる事実はその境界に；
3. 一つのファイルの公開コントラクトはその先頭のドキュメントに；
4. 自明でないローカルな不変条件は該当ブロックの隣に。

より遠いアーティファクトを使うのは、その対象読者や横断的なスコープが本当にそれを必要とする場合に限り、その場所が正典である理由を明記すること。上位レベルの要約は、下位レベルのソースを特定し、その意味を保持し、競合する定義を作らない場合に限り、それを圧縮して構わない。

## Generation and duplication

- 結果が読みやすく、レビュー可能で、対象読者にとって十分である限り、コード、スキーマ、アノテーション、その他の権威あるデータからの生成を優先すること。必要な意図や利用ガイダンスを欠くことになる場合、生成の方が望ましいと主張しないこと。
- 一つの事実については一つの正典的な定義を維持すること。競合するコピーは要約かリンクに置き換え、避けられない投影（projection）はすべて同じ変更の中で更新すること。
- 生成された出力は派生アーティファクトとして扱い、第二の真実の源（second source of truth）として扱わないこと。

## Process-artifact isolation

出荷されるドキュメントは、パスや文言が変わることが見込まれる一時的な計画メモ、タスクリスト、調査用スクラッチノート、チェックリストに依存してはならない。永続的な論拠は安定した意思決定・設計アーティファクトに移し、ユーザーに見える振る舞いは直接記述すること。プロセスアーティファクト同士は、それぞれの限定された作業空間の中でなら互いを参照してよい。

## Overrides

例外は、その理由、影響を受けるアーティファクト、責任者、フォローアップ条件が記録されている場合にのみ受け入れること。同期を省略する黙示の要求は拒否する——耐久性のある理由のない例外は、ドリフトと見分けがつかない。
