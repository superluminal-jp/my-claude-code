# Model and Effort Routing（モデルと労力のルーティング）

独立した作業単位ごとに、確実に完了できる最も能力の低いモデルと最も低い労力レベルを使う。ルーティングは、必要な判断、曖昧さ、依存の広がり、影響範囲によって決め、作業の大きさだけでは決めない。

## Capability tiers（能力層）

| 層 | エイリアス | 使う場面 |
|---|---|---|
| 最高能力 | `fable` | 曖昧、または影響が大きい作業: システムアーキテクチャ、難度の高い根本原因分析、横断的な変更、長期にわたる調整、誤りが広範に波及する最終的な意味判断。 |
| 高能力 | `opus` | 相当なエンジニアリング判断が要る作業: 複雑な実装、自明でないデバッグ、リファクタリング、仕様や計画の分析、コードレビュー、トレードオフの評価。 |
| バランス型 | `sonnet` | 通常の実装の既定: 範囲が明確な機能、定型的なバグ修正、テスト、マイグレーション、中程度のリファクタリング、目的は明確だが実行が自明でないその他の作業。 |
| 高効率 | `haiku` | 決定的、局所的、または反復的な作業: リポジトリ検索、Git の整理、フォーマットや lint の修正、リネーム、import、コメントや docstring、ドキュメントや変更履歴の同期、単純なテストの追加。 |

優先順: 判断する → より高い能力、実装する → バランス型、機械的に実行する → 高効率。

## Escalation and hand-back（エスカレーションと引き戻し）

- エスカレーションするのは、現在の層が正しい振る舞いを決定できない、意味上の曖昧さに直面する、アーキテクチャ上のトレードオフを要する、または推論に起因する理由で失敗する場合に限る。
- 作業が大きい、または反復的だというだけでエスカレーションしない。決定的な作業は分解または並列化する。
- より高能力なモデルが不確実な部分を解決した後は、範囲の定まった実装、検証、後始末を、実行可能な限り低い層へ委ねる。

## Effort and delegation（労力と委譲）

- モデルの能力と推論の労力は、別々の制御として扱う。
- `low` は機械的または自明な作業、`medium` は通常の実装の既定、`high` は複雑な推論や重大な影響のあるレビューに向く。`xhigh` と `max` は、最も深い推論が実質的に役立ち、選択したモデルが対応している例外的な場合に限る。
- 委譲するときは、サブエージェントのモデルと労力の両方を意図して選ぶ。
- 自明な逐次作業や単一ファイルの作業は、サブエージェントより直接実行を優先する。作業が独立している、並列化できる、または分離した文脈の利点がある場合にサブエージェントを使う。

各作業単位に、その判断、曖昧さ、依存の広がり、影響範囲から導かれる層と労力があり、すべてのエスカレーションが上記の条件のいずれかを示しているとき、ルーティングは十分であるといえる。
