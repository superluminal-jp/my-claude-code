# Cloud Platform Research

プロバイダー固有の質問には、記憶や静的な機能一覧ではなく、現行の一次情報の根拠に基づいて回答する。

## 調査の契約を確立する

以下を特定する。

- プロバイダーとサービス;
- 根拠を必要とする正確な主張または判断;
- 回答を左右しうるリージョン、APIバージョン、ランタイム、言語、日付の制約;
- ユーザーが必要としているのが説明か、比較か、実装ガイダンスか、正確な引用か。

欠けている項目が結果を大きく左右する場合にのみ質問する。それ以外の場合は、用いた狭い前提を明記する。

## 現行の公式機能を発見する

プロバイダーのドキュメントが利用不可能だと結論づける前に、利用可能なツール探索の仕組みを使う。タスク実行時にプロバイダーの公式情報源を選択する。

| 対象 | 優先すべき公式機能 |
|---|---|
| AWSサービスとリージョン提供状況 | `aws-knowledge` または `aws-documentation` |
| Amazon Bedrock AgentCore | `bedrock-agentcore` |
| Strands Agents | `strands-agents` |
| Google Cloudおよび Google 開発者向け製品 | `google-developer-knowledge` |
| Microsoft Azureおよび Microsoft Learn | `microsoft-learn` |

この表は優先順位を示すものであり、当該機能が設定済み・認可済み・正常稼働していることの証明ではない。現在利用可能なツールを発見し、サーバーから返される指示に従う。OAuthの状態を推測したり、ツール、スキル名、パラメーター、レスポンスを作り出したりしない。

AWSのエージェントスキルに関する質問については、公式機能がスキルレジストリの検索を提供している場合、まず `agent_skills` トピックを検索し、その検索によって返された正確な名前のみを取得する。レジストリの識別子を推測しては決してならない。

## 調査し、突き合わせる

1. その主張に回答できる、最も範囲の狭い公式ドキュメント情報源を検索する。
2. 一次ページまたはAPIリファレンスを開き、適用範囲、バージョン、リージョン、公開の鮮度を確認する。
3. 重要な判断については、該当する製品ガイドとAPIまたは制限のリファレンスの両方が存在する場合、それらを突き合わせて裏付けを取る。
4. 矛盾がある場合は、製品契約により近い情報源、より具体的・最新の範囲を優先して解決する。矛盾が残る場合は、黙って選択せずにその旨を明記する。
5. 複数の情報源を組み合わせた推論であることを明確に示す。

公式ドキュメントツールが利用できない場合は、ライブのプロバイダードキュメントに到達できなかったことを明記する。アクセス可能であれば他の現行の公式プロバイダーページを使用し、そうでなければ既存の知識から明確に限定を付けた回答のみを行い、未検証のまま残る部分を明示する。

## 回答の契約

- 直接的な回答または推奨事項から始める。
- 現在値が重要となる各主張の隣に公式ページを引用する。
- 検証済みのプロバイダーの挙動と、アーキテクチャ上の助言およびローカルでの実装上の選択とを区別する。
- リージョン、バージョン、日付、前提条件、制限、例外は、それらがユーザーの判断に影響する場合にのみ含める。
- 過剰な引用をせず、正確に要約したうえで直接リンクを提示する。

## 完了確認

- プロバイダー固有の重要な主張はすべて、現行の一次情報による裏付けがあるか、明示的に未検証とされている。
- ツールの利用可能性と認可状態は、想定ではなく観測によって確認されている。
- 情報源をまたぐ推論と、未解決の鮮度リスクにはラベルが付いている。
- 回答は、プロバイダー固有の依頼を無関係なプラットフォーム全般の助言へと広げていない。
