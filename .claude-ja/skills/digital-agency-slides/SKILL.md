# デジタル庁スライド

デッキを固定サイズの 16:9 キャンバス上の 1 つの HTML ファイルとして作成し、デジタル庁自身のスタイルシートでスタイリングしたうえで、ネイティブかつ編集可能な図形として PowerPoint に変換する。納品形式は PowerPoint であるため、作成面の設計は PowerPoint が表現できる範囲によって決まる。その逆ではない。

## すべての前提となる不変条件

1 スライドは **1280 x 720 CSS ピクセル**である。96 px/in において、これはちょうど 13.333 x 7.5 インチ、すなわち PowerPoint の標準 16:9 スライドと一致する。したがって:

```
1 CSS px = 0.75 pt = 9525 EMU        厳密な値であり、丸めも拡大縮小も発生しない
```

32 px の見出しは 24 pt の見出しになり、左端から 64 px の要素は左端から 0.667 インチの位置に配置される。パイプラインのどの段階でも拡大縮小は行われない。キャンバスサイズを変更すれば、以下のすべての保証も失われる。

## 対象範囲

- プレゼンテーションスライドと、その `.pptx` への変換。ブラウザ上に留まるページ、アプリケーション UI、対話的なダッシュボードは対象外とする。
- 成果物はデッキの内容そのものである。周辺プロジェクトの構造を変更したり、そのプロジェクトが持たないビルドシステムを導入したりしてはならない。
- 構築前に重大な曖昧さを解消する。想定読者、デッキが求める意思決定、支配的メッセージ、スライド枚数の上限、ファイルの提示方法である。2 つの妥当な解釈が異なるデッキを生むならば確認し、そうでなければ前提を明示したうえで進める。

## リファレンスを段階的に読み込む

| 読む対象 | いつ読むか |
|---|---|
| `references/slide-design.md` | デッキの論理構成を組み立てるとき、レイアウトを選ぶとき、書体と色を決めるとき |
| `references/authoring-contract.md` | スライドの HTML を記述・編集するとき — コンバータが読み取るマークアップ契約 |
| `references/pptx-conversion.md` | 変換を実行するとき、その検出結果を読むとき、再現性の限界を説明するとき |
| `references/asset-sourcing.md` | 公式資材を取得・更新するとき、または帰属表示を記述するとき |

DADS のバージョン、トークン名、コンポーネントのクラス名、パッケージ API を記憶から引用してはならない。取得済みの資材、インストール済みパッケージ、またはライブの公式情報源から読み取ること。

## 同梱物

| パス | 内容 |
|---|---|
| `assets/slide.css` | このスキル独自の 16:9 レイアウト層。DADS のトークンカスタムプロパティのみに依拠する。DADS コンポーネントライブラリではない。 |
| `assets/deck-template.html` | 全レイアウトを網羅した実動作の 9 枚組デッキ。複製して使い、直接編集しない。 |
| `scripts/setup.sh` | Python の依存関係と Chromium をプロジェクトローカルの仮想環境に導入する |
| `scripts/fetch-dads-assets.sh` | 公式 DADS スタイルシートを、作業時点でデッキのワークスペースに解決する |
| `scripts/deck.py` | `lint`、`preview`、`pptx`、`ir` — パイプライン全体 |
| `scripts/extract_slides.js` | ブラウザ上でレイアウト済みデッキを実測し、変換用 IR を出力する |

デジタル庁の公式コードはここに同梱していない。デッキの構築時に取得するため、デッキは常に最新のアップストリーム参照実装を用いる。

## ワークフロー

### 1. エディタを開く前にデッキを定義する

想定読者、求める意思決定または行動、唯一の支配的メッセージ、スライド枚数の上限、提示の状況(投影・印刷・単独での閲読)を確定する。PowerPoint が本当に必要かを確認する。ブラウザでしか読まれないのであれば、以下の変換上の制約を負う意味はない。

### 2. スライドではなく、論理構成を書く

各スライドに 1 つの主張を与え、それ単体で成立する完全な文として記述する。各セクションのスライドが合わさってそのセクションの主張を支え、各セクションが合わさってデッキの支配的メッセージを支えるように並べ、グループ化する。見出しが話題のラベル(「現状について」)であるスライドには、まだ主張がない。詳細とレイアウトカタログは `references/slide-design.md` を参照。

### 3. ワークスペースを用意する

```sh
mkdir -p my-deck && cd my-deck
cp "$CLAUDE_SKILL_DIR/assets/deck-template.html" deck.html
cp "$CLAUDE_SKILL_DIR/assets/slide.css" .
bash "$CLAUDE_SKILL_DIR/scripts/fetch-dads-assets.sh" . table list divider
bash "$CLAUDE_SKILL_DIR/scripts/setup.sh"
```

デッキが実際に使用する公式コンポーネントのスタイルシートを追加する。名前が解決できない場合、取得スクリプトがアップストリームで利用可能なものを一覧表示する。

### 4. スライドを構築する

レイアウトを自作せず、テンプレートのレイアウトカタログから選ぶ。DADS が既に定義しているものには公式の `dads-*` クラスと DADS の書体・色トークンを使い、スライドのジオメトリにはこのスキルの `sld-*` クラスを使う。すべてのスライドをキャンバスとセーフエリアの内側に収める。ネイティブ変換される対象、ラスタライズされる対象、`data-pptx` による上書きを含むマークアップ契約は `references/authoring-contract.md` にある。

### 5. 変換前に検査する

```sh
.venv/bin/python "$CLAUDE_SKILL_DIR/scripts/deck.py" lint deck.html
.venv/bin/python "$CLAUDE_SKILL_DIR/scripts/deck.py" preview deck.html -o preview
```

`lint` は、切れたテキスト、スライド外やセーフエリア帯にある内容、可読性の下限を下回る書体、不足したコントラスト、欠落した代替テキスト、コンバータが到達できない装飾を報告する。エラーをゼロにし、すべての警告に判断を下すこと。そのうえで**プレビュー画像を必ず目で見る**。スライドが読みにくいことは、リンタには判定できない。

### 6. 変換し、結果を確認する

```sh
.venv/bin/python "$CLAUDE_SKILL_DIR/scripts/deck.py" pptx deck.html -o deck.pptx
```

このコマンドは、`--allow-findings` が指定されない限りエラーのあるデッキの変換を拒否し、ネイティブに出力された図形とラスタライズされた図形の数を報告する。大半がラスタライズされたデッキは目的を失っている。原因を突き止め、マークアップを修正すること。`.pptx` を開き、テキストが選択可能であること、表が実際の表であること、発表者ノートが届いていることを確認する。対応関係、オプション、既知の限界は `references/pptx-conversion.md` にある。

### 7. 完了報告

報告する内容: 支配的メッセージとデッキがそれをどう支えているか、lint の検出結果と各々への対処、ネイティブ図形とラスタライズ図形の比率、取得した公式資材とそのコミット、そして読み手が意図どおりにファイルを見るために導入が必要なもの(とりわけデッキのフォント)。帰属表示は `references/asset-sourcing.md` の規則に従う。

## ガードレール

- **再現性はフォントで決まる。** ジオメトリはブラウザのフォントメトリクスで実測される。PowerPoint は同じテキストを自身のメトリクスで組み直す。ファイルを開く環境にデッキのフォントを導入するか、変換時に `--font` で差し替え、どちらを行ったかを明示すること。
- **変換の問題を回避するためにスライド全体をラスタライズしてはならない。** スライドの画像は編集も検索も翻訳も読み上げもできない。本当に必要な最小の要素だけをラスタライズし、代替テキストを与えること。
- **`::before` / `::after` で描いた装飾は変換されない。** 擬似要素には DOM ノードも計測可能なボックスも存在しない。実要素を使うこと。
- 色・位置・図版だけに意味を担わせてはならない。テキストでも同じことを述べること。
- デッキがデジタル庁の製品である、またはデジタル庁の推奨を受けていると称してはならない。
- DADS のトークン、コンポーネントクラス、バージョン番号を創作してはならない。このスキルが追加したものは、DADS ではなくこのスキル独自のものとして明示すること。
- デジタル庁のイラストレーション、アイコン、Figma データをデッキに複製してはならない。これらは MIT ライセンスのコードとは別の利用条件に従う。
