# Feature Specification: 用語の形をその分野で決め、訳語を作らない

**Feature Branch**: `fix/term-form-follows-field`

**Created**: 2026-11-02

**Status**: Draft

**Input**: User description: "Versionを版と言ったり、gateを門と言ったり、oldを古いと言ったり、回答や生成物の日本語が不自然なことが多くある。傾向を調査して対策を提案"。その後の指示: "Data scientist, AI Engineer, Astrophysics researcher として自然に使う語彙英語で使い慣れている語彙は訳さなくて良い。しかし汎用性のためにroleは明示したくない。" "Readerに合わせるのではなくトピックに合わせるようにしたい" "例なしで書き換え" "実装して"

**Authority**: 本仕様が正である。spec 051 が常時ルールに加えた「Prefer the plain word when it is exact」を置き換える。spec 051 のほかの義務(前提の提示、初出の用語の定義、比喩・類推の禁止)は変えない。

## 背景

リポジトリの日本語の生成物では、spec 051 のコミット(2026-10-28)の前後で、定着したカタカナ語が和語・漢語の造語に入れ替わった。変更前は「ツリー」65件・「木」5件、変更後は「ツリー」1件・「木」52件である。「指摘」と「所見」の比も 18:20 から 0:25 に変わった。英語の "plain word"(専門用語でない語)が、日本語では「カタカナ語でない語」と解釈されたと推定する。

用語の指示を含まない9課題を新しいサブエージェントで2巡実行したところ、18件中7件に造語が出た(言い換えが自然な箇所を除くと3件)。造語は「版(version)」「木・節(tree・node)」「枝(branch)」に集中し、7件中4件は用語を定義する括弧書きや定義文の中にあった。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 専門用語がその分野で使われる形で書かれる (Priority: P1)

利用者が日本語で専門的な内容を尋ねる、または日本語の文書を作らせる。回答に出る専門用語は、その用語が属する分野の実務者が日本語で書く形になる。日本語の訳語が定着した語はその訳語、カタカナ語や英語のまま使われる語はその形で書かれる。どの形が使われているか分からない語は原語のまま残り、新しい訳語は作られない。初学者に向けた分かりやすさは、用語を言い換えることではなく、定義を添えることで得る。

**Why this priority**: 造語は読み手が文献・コード・ツールの語と照らし合わせることを妨げ、意味がずれることもある(「肩書き」は shoulder の訳として使われたが、本来は職名を指す)。常時ルールの1文が原因と推定されるため、全セッションに影響する。

**Independent Test**: 常時ルールが下記の義務を持ち、ルール層の構造テスト(5ファイル、相互参照なし、容量の上限)が通ること、Claude.ai 用と ChatGPT 用のプロンプトが同じ義務を持ち、記載の文字数が実数と一致することを確かめる。

**Acceptance Scenarios**:

1. **Given** 読み手向け構造のルール、**When** 読む、**Then** 次が書かれている: 各用語を、その分野の実務者が出力言語で使う形で書くこと。その形が分からなければ原語を残すこと。訳語を作らないこと、およびその理由(用語はその分野の文献・コード・ツールの語と一致しなければならない)。用語を平易にするのは定義によってであり、置き換えによってではないこと。特定の語の例は含まない。
2. **Given** ルール層、**When** 構造テストを実行する、**Then** ルールは5ファイルのまま、相互参照がなく、常時ロードの合計が基準値未満である。
3. **Given** Claude.ai 用のプロンプト、**When** 読む、**Then** 同じ義務を持ち、記載の文字数が実際のブロックの文字数と一致し、自主上限(約7,000字)以内である。
4. **Given** ChatGPT 用のプロンプトの「More about you」、**When** 読む、**Then** 同じ義務を持ち、記載の文字数が実際のブロックの文字数と一致する。

---

### Edge Cases

- 話題が混ざる場合(天体物理のデータ処理での CI など)は、会話全体の話題ではなく、その用語が属する分野で形を決める。
- 定着した形が分野内で分かれている、または確かめられない語は、原語のまま残す。
- 用語に定義を付けるかどうかは、従来どおり読み手で決める(「Assume the reader is new to the subject unless the user's own messages show otherwise」と「Skip the definition only for a term the user has already used correctly」は変えない)。語の形は分野で決め、説明の量は読み手で決める。
- 訳さずに残すのは分野の用語だけである。文の組み立てと日常語は出力言語で書く。
- 一般向けの文書でも分野の用語を使い、定義で補う。「公用文作成の考え方」(文化審議会、2022)は外来語の扱いを読み手と目的で決めるとしており、本仕様はその点で異なる。理由は、文書ごとに語の形が変わらず、文献・コード・ツールと照らし合わせられることである。言い換えが必要な成果物は、そのスキルの中で上書きする。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 常時ロードの読み手向け構造のルールは、User Story 1 の受け入れシナリオ1の義務を持ち、「Prefer the plain word when it is exact」の文を持ってはならない。
- **FR-002**: ルール層の構造テストは、FR-001 の義務(用語の形を分野で決めること、訳語を作らないこと)を検査しなければならない。
- **FR-003**: Claude.ai 用のプロンプトは同じ義務を持ち、文字数の記載を更新しなければならない。
- **FR-004**: ChatGPT 用のプロンプトの「More about you」は同じ義務を持ち、文字数の記載を更新しなければならない。全文ブロック(上限5,000字)と簡易ブロック(上限1,500字)は言語の指示を持たないため変えない。
- **FR-005**: README(英・日)はルールの内容の要約を変更後の挙動に合わせなければならない。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: `tests/run-config-pyramid.sh` が新しい検査を含めてすべて通る。新しい検査は、ルールの変更前に失敗することを確かめる。
- **SC-002**: 常時ロードの合計が基準値 20,126 バイト未満である。
- **SC-003**: Claude.ai 用のブロックが7,000字以下で、記載の文字数と一致する。ChatGPT 用の各ブロックの文字数が記載と一致する。

## Assumptions

- 「トピック」は、会話全体の話題ではなく、その用語が属する分野と解釈する(確度: 中〜高)。話題が混ざっても形が揺れないためである。
- ルールの文に特定の語の例を入れない(利用者の指示)。例による固定がないぶん、基準の読み違いは指示文では止められない。止める手段(対訳表と機械検査)は本仕様の範囲外とする。
- 利用者の役割(Data scientist など)は書かない(利用者の指示)。分野の慣例が、役割に依存せず同じ効果を持つ。
- 効果(造語の出現率の低下)は本仕様では測らない。同じ18課題で前後を比べる実験を後続の作業とする(確度: 該当なし)。
