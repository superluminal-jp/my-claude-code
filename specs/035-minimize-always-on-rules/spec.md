# 機能仕様書: 常時ロードルールの最小化と強制力の復元

**機能ブランチ**: `035-minimize-always-on-rules`

**作成日**: 2026-08-30

**ステータス**: ドラフト

**入力**: ユーザー記述: 「claude code の最新のドキュメント、プラクティス、モデル性能を考慮して `.claude/rules/` の各ルールについて、必要性を再検討したい」→ 分析結果のうち推奨 1・2・3・6 を採用、4（`claudeMdExcludes`）と 5（シンボリックリンク同期）は対象外と明示。加えて「最小化」の方針を全ルールに適用。

## ユーザーシナリオとテスト *(必須)*

### ユーザーストーリー1 - 作業用の文脈を取り戻す (優先度: P1)

開発者が任意のプロジェクトで Claude Code を起動する。セッション開始時に読み込まれる常時指示が必要最小限に絞られているため、コードを読むための文脈が広く残る。指示の総量が減ったことで、残った指示への遵守率も上がる。

**この優先度の理由**: 常時ロードは全プロジェクト・全セッションに課金される固定費であり、削減効果が最も広く波及する。公式ドキュメントは「長いファイルは文脈を消費し遵守率を下げる」と明記しており、量の削減はそれ自体が品質改善でもある。

**独立したテスト**: `.claude/rules/*.md` の合計バイト数を変更前後で計測し、削減率を確認する。各ファイルが公式指針の 200 行未満に収まっていることを確認する。他のストーリーを実装しなくても単独で価値が出る。

**受け入れシナリオ**:

1. **Given** 変更前の `.claude/rules/` が合計 36,165 バイト、**When** 最小化を適用、**Then** 合計が 16,000 バイト以下（55% 以上の削減）になる
2. **Given** 最小化後のルール群、**When** 各ファイルの行数を数える、**Then** すべて 200 行未満である
3. **Given** 削除された任意の指示、**When** その削除根拠を問う、**Then** 「モデルのネイティブ挙動」「ハーネスが注入済み」「指定の退避先へ移設」のいずれかが具体的に示せる

---

### ユーザーストーリー2 - 資格情報保護が実際に効く (優先度: P1)

開発者が、あるいは Claude 自身が `.env` や `~/.ssh/` 配下のファイルを読もうとする。散文の方針ではなく設定による拒否が働き、読み取りが実際に止まる。

**この優先度の理由**: 現状 `.claude/rules/permissions.md` は本文自らが「nothing in Claude Code enforces it automatically」と述べており、最も深刻度の高い保護が助言に留まっている。公式ドキュメントは「設定による規則はクライアントが強制する。CLAUDE.md は強制層ではない」と区別しており、散文を設定に変換できる箇所は変換するのが正しい。

**独立したテスト**: `.claude/settings.json` の `permissions.deny` に対象パターンが存在することを確認し、対象パスへの `Read` が拒否されることを確認する。

**受け入れシナリオ**:

1. **Given** `permissions.deny` が設定済み、**When** `.env` の読み取りを試みる、**Then** 拒否される
2. **Given** 同上、**When** `.claude/keybindings.json` など正当なファイルを読む、**Then** 拒否されない
3. **Given** ADR-0006 が `permissions` ブロックの全廃を Accepted として記録済み、**When** その一部を復元する、**Then** 0006 を書き換えずに supersede する新規 ADR が存在する

---

### ユーザーストーリー3 - 列挙の二重管理をやめる (優先度: P2)

保守者が新しいスキルを `.claude/skills/` に追加する。ルーティング表への転記が不要になっているため、追加漏れによるドリフトが構造的に起こらない。

**この優先度の理由**: 現に `adr` / `apple-notes` / `apple-reminders` の 3 スキルが必須ルーティング表から欠落しており、ドリフトが仮説ではなく実測された事実である。ハーネスは全スキルの名称・説明・トリガー語句を自動注入するため、手書きの列挙は重複でありドリフト源でしかない。

**独立したテスト**: `.claude/skills/` の実体と、ルール・CLAUDE.md 内のスキル列挙を突き合わせ、乖離が生じ得ないことを確認する。

**受け入れシナリオ**:

1. **Given** `.claude/skills/` に speckit 以外のスキルが 10 個、**When** ルールと CLAUDE.md を検査、**Then** 実体と矛盾する列挙が残っていない
2. **Given** 最小化後の `skill-routing.md`、**When** 内容を検査、**Then** 複合作業の連鎖と否定的境界（`scrum-master` に流さない範囲）のみが残っている

---

### ユーザーストーリー4 - 移設した根拠を辿れる (優先度: P3)

保守者がルールの根拠（準拠規格、§7 の設計意図、参考文献）を確認したくなる。常時文脈からは外れているが、名前の付いた場所に残っており、ルール本文からその場所が指されている。

**この優先度の理由**: 削除ではなく移設であることを担保する。根拠を失うと Core Principle #3（トレーサビリティ）に反する。ただし常時ロードする必要はない。

**独立したテスト**: ルール本文から退避先へのリンクを辿り、移設した全節が存在することを確認する。

**受け入れシナリオ**:

1. **Given** §0 標準規格表・§7.2/7.3 の解説・References を移設、**When** 退避先を開く、**Then** 内容が失われず存在する
2. **Given** 退避先の配置、**When** その位置を検査、**Then** `.claude/rules/` 配下ではない（同ディレクトリは全 `.md` を再帰的に自動ロードするため）
3. **Given** 移設によって節番号や見出しが変わった、**When** `README.md` / `README.ja.md` / `install.sh` / `docs/` を検査、**Then** 移設先を指さない壊れた参照が残っていない

---

### エッジケース

- `permissions.deny` のパターンが広すぎると正当な作業を過剰に阻害する。特に現行方針の「ファイル名に `secret` / `credential` / `token` / `key` を含むもの」を素朴に `**/*key*` へ機械変換すると、`.claude/keybindings.json` や `monkey.ts` のような無関係なファイルまで拒否される。
- `.claude/settings.json` は `install.sh` により `~/.claude/` へ同期され、**全プロジェクト**に波及する。ADR-0006 がこの波及を負の帰結として記録していたのと同じ経路が、今回は正の帰結として働く。この非対称性を新 ADR に明記する必要がある。
- §7 は本ブランチの親コミット `a884d6f`（`origin/main` 未反映）で追加されたばかりであり、その直後に同じ節を再構成することになる。§7 の規範は残し解説のみを移設するため撤回ではないが、履歴上は追加と再編が連続する。
- ルールから削除した指示が実はハーネスのネイティブ挙動ではなかった場合、挙動が静かに退行する。削除の根拠は個別に検証されねばならない。
- `.claude/rules/` は再帰的に全 `.md` を読み込むため、退避先を誤って同ディレクトリ配下に置くと削減効果がゼロになる。

## 要求事項 *(必須)*

### 機能要求

**強制力の復元**

- **FR-001**: `.claude/settings.json` は資格情報パスに対する `permissions.deny` を持たなければならない。対象は `.env` および `.env.*`、`secrets/` / `credentials/` / `.aws/` / `.ssh/` 配下、および `.pem` / `.p12` / `.pfx` の秘密鍵とする。
- **FR-002**: `permissions.deny` のパターンは、過剰阻害を避けるため字句的に精密でなければならない。ファイル名の部分一致（`secret` / `credential` / `token` / `key` を含む名前）はグロブへ機械変換してはならず、方針文としてルールに残す。
- **FR-003**: ADR-0006（Accepted）の決定の一部を覆すため、0006 を改変せずに supersede する新規 ADR を作成しなければならない。ADR は全プロジェクトへの波及と、部分復元にとどめた理由を記録する。
- **FR-004**: `.claude/rules/permissions.md` は、設定として表現できない項目のみを残さなければならない。すなわちプロジェクト限定インストール、AWS のリソース変更操作に対する毎回の確認（ADR-0009）、および FR-002 の部分一致方針。設定で強制される項目は設定側を正本として参照する。

**常時ロード量の最小化**

- **FR-005**: `.claude/rules/live-documentation.md` は常時必要な強制中核のみを保持しなければならない。§1〜§7 の判定規則、Override Handling、Out of Scope がこれに当たる。
- **FR-006**: §0 のライフサイクル標準規格表、§7.2/§7.3 の論拠と解説、References は、`.claude/rules/` 配下**以外**の指定された退避先へ移設しなければならない。移設先はルール本文から参照されなければならない。
- **FR-007**: `.claude/rules/skill-routing.md` は、複合作業の連鎖規則と否定的境界のみを保持しなければならない。個々のスキルの列挙とトリガー語句の再掲は、ハーネスが自動注入するため削除する。
- **FR-008**: `.claude/rules/clarifier.md` は ask/proceed の判断ゲートのみを保持しなければならない。曖昧性パターンの目録と References は `clarifier` スキルへ委ねる。
- **FR-009**: `.claude/rules/git-workflow.md` はリポジトリ固有の規約のみを保持しなければならない。すなわち `<type>/<short-kebab-summary>` のブランチ命名、Spec Kit ブランチの例外、PR 本文の What / Why / How verified。Conventional Commits の文法、命令形、50/72 規則、および「頼まれた時だけコミットする」等のハーネス既定は削除する。
- **FR-010**: `.claude/rules/mcp.md` はルーティング規則と AWS 公式スキルレジストリの 2 段呼び出し手順（`aws___search_documentation` を `topics: ["agent_skills"]` で呼び、返された正確な `skill_name` で `aws___retrieve_skill` を呼ぶ）を保持しなければならない。サーバカタログ表は `.mcp.json` およびハーネスが注入するサーバ自己記述と重複するため削除する。

**構成の整合**

- **FR-011**: `.claude/CLAUDE.md` から 5 行の `@.claude/rules/...` インポートを削除しなければならない。`paths:` フロントマターを持たない `.claude/rules/*.md` は無条件にロードされるため、これらのインポートは冗長である。
- **FR-012**: `.claude/CLAUDE.md` および `.claude/rules/skill-routing.md` は、実体とずれ得るスキル列挙を保持してはならない。
- **FR-013**: 移設・削除の結果として、`README.md`、`README.ja.md`、`install.sh`、`docs/` 配下に、存在しない節やファイルを指す参照が残ってはならない。
- **FR-014**: 削除された各指示は、削除根拠が「モデルのネイティブ挙動」「ハーネスが注入済み」「指定の退避先へ移設」のいずれかに分類され、記録されなければならない。

### 主要エンティティ

- **常時ロードルール**: `.claude/rules/` 直下の `.md` 群。`paths:` を持たない限りセッション開始時に無条件でロードされ、`.claude/CLAUDE.md` と同じ優先度を持つ。今回 `paths:` の導入は行わない。
- **強制設定**: `.claude/settings.json` の `permissions` ブロック。クライアントが強制し、モデルの判断に依存しない。`install.sh` によりユーザスコープへ同期される。
- **退避先ドキュメント**: 常時ロードされない参照資料。`.claude/rules/` 配下に置くことはできない。
- **決定記録 (ADR)**: `docs/adr/`。Accepted 後は不変で、supersede のみ可能。

## 成功基準 *(必須)*

### 測定可能な成果

- **SC-001**: `.claude/rules/*.md` の合計が 36,165 バイトから 16,000 バイト以下へ縮小する（55% 以上の削減）。
- **SC-002**: `.claude/rules/` 配下のいずれのファイルも 200 行を超えない（変更前は `live-documentation.md` が 158 行で最大、削減後はさらに下回る）。
- **SC-003**: `.env` 相当のパスへの読み取りが設定により拒否される一方、`.claude/keybindings.json` のような正当なファイルは拒否されない。両方向が確認できる。
- **SC-004**: `.claude/skills/` の実体と矛盾するスキル列挙が、リポジトリ内のルールおよび CLAUDE.md に 0 件である。
- **SC-005**: 移設した節（§0 標準規格表、§7.2/§7.3 解説、References）が退避先に 100% 存在し、ルール本文から到達できる。
- **SC-006**: `README.md` / `README.ja.md` / `install.sh` / `docs/` に、移設・削除により壊れた参照が 0 件である。
- **SC-007**: ADR-0006 は改変されておらず、その決定の一部を覆す新規 ADR が存在し、両者が相互に参照されている。

## 前提条件

- **列挙の扱い**: 「スキル列挙を追加するか、列挙自体をやめるか」の二択について、採用方針「最小化」に従い**列挙をやめる**方を既定とする。ハーネスが全スキルの説明とトリガー語句を自動注入することが確認済みであるため、列挙は重複かつドリフト源である。
- **退避先**: `docs/` 配下とする。同ディレクトリは既に `docs/adr/`、`docs/claude-code-config-tips.md` 等で散文の置き場として確立しており、かつ自動ロードされない。`.claude/rules/` 配下に置けないことは技術的制約であって選好ではない。
- **`paths:` フロントマターは今回導入しない**: 対象 7 ルールはいずれもファイル種別ではなく話題で発火するため、パススコープが適合しない。将来の選択肢として残す。
- **`thinking-lenses.md` は現状維持**: 17 行と最小であり、削減余地が乏しい。ただし遵守が観測不能である旨は既知の論点として残る。
- **ベースライン計測はプロジェクトスコープ**: 36,165 バイトは §7 追加後（`a884d6f`）の `.claude/rules/` 合計。ユーザスコープの `~/.claude/` はまだ §7 を含まず、`install.sh` の次回実行で追随する。
- **本ブランチは `a884d6f` の上に積まれている**: §7 が `origin/main` 未反映のため、本変更は §7 に依存する。
- **`claudeMdExcludes` とシンボリックリンク同期は対象外**: 分析時の推奨 4・5 として明示的に除外された。
