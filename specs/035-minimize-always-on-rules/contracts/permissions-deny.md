# 契約: `permissions.deny` の確定形

**対象**: `.claude/settings.json` の `permissions.deny`
**根拠**: [research.md](../research.md) D1〜D4
**満たす要求**: FR-001, FR-002

## 確定形

```json
{
  "permissions": {
    "deny": [
      "Read(**/.env)",
      "Read(**/.env.*)",
      "Read(**/*.pem)",
      "Read(**/*.p12)",
      "Read(**/*.pfx)",
      "Read(**/secrets/**)",
      "Read(**/credentials/**)",
      "Read(**/.ssh/**)",
      "Read(**/.aws/**)",
      "Read(~/.ssh/**)",
      "Read(~/.aws/**)"
    ]
  }
}
```

## 1 行ごとの根拠

| パターン | 対象 | 形式を選んだ理由 |
|---|---|---|
| `Read(**/.env)` | 任意の深さの `.env` | ベア名 `.env` でも等価だが、`**/` を明示して深さ非依存であることを読み手に見せる |
| `Read(**/.env.*)` | `.env.local`、`.env.production` 等 | 単独の `*` は 1 パスセグメント内でのみ一致するため、`.env.` 接頭辞のバリアントを正しく捕捉する |
| `Read(**/*.pem)` / `(**/*.p12)` / `(**/*.pfx)` | 秘密鍵 | 拡張子が確定しているため、部分一致に頼らず正確に指定できる（D2） |
| `Read(**/secrets/**)` / `(**/credentials/**)` | 資格情報ディレクトリ | deny 規則では単一セグメント形 `secrets/**` も任意深さに一致するが、`**/` 明示で allow 規則との挙動差に依存しない書き方にする |
| `Read(**/.ssh/**)` / `(**/.aws/**)` | プロジェクト内に置かれた複製 | カレントディレクトリ配下を対象 |
| `Read(~/.ssh/**)` / `(~/.aws/**)` | 本来の位置 | `~/` はホーム基準で、プロジェクト設定・ユーザ設定のどちらに置かれても同じ場所に解決される（D1） |

## 禁止事項

- **単一先頭スラッシュ `/path` を使わない。** 設定ソース基準でアンカーされるため、`.claude/settings.json` がプロジェクト設定として読まれるときは `<主作業ディレクトリ>/path`、`install.sh` によって `~/.claude/settings.json` になったときは `~/.claude/path` に解決される。同一の行が配置先で別の意味を持つ（research.md D1）。
- **`//` 絶対パスによるファイルシステム全体の走査を使わない。** ユーザの他プロジェクトやバックアップにまで及ぶ過剰な適用範囲。
- **ファイル名の部分一致をグロブ化しない。** `Read(**/*key*)` は `.claude/keybindings.json` に一致する。deny 規則は allow による例外を持てないため、過剰阻害は後から緩和できない（research.md D2）。この方針は `permissions.md` に散文として残す。
- **`Edit` deny を重複して追加しない。** `Read` deny がすでに Edit / Write を覆う。追加で得られるのは `NotebookEdit` の被覆のみで、対象パスに `.ipynb` は現実的に存在しない（research.md D3）。

## 受け入れる帰結

以下は意図した副作用である。隠さず ADR-0014 に記録する。

1. **`.env` の作成・編集もできなくなる。** `Read` deny は同一パスの Edit / Write（新規作成を含む）を塞ぐ。`.env.example` から `.env` を生成するような作業は、以後ユーザ自身が行う必要がある。
2. **`.env.example` / `.env.sample` も読めなくなる。** `**/.env.*` に一致するため。これらは通常安全なテンプレートであり、失われる利便性は実在する。deny は例外を持てないため、除外したい場合の唯一の手段はパターンを削ることである。
   - **代替案（実装時に選択可能）**: `Read(**/.env.*)` を落とし、`.env` 本体のみを塞ぐ。方針文書が挙げる `.env.*` の保護は弱まる。
   - **本契約の既定**: `**/.env.*` を**残す**。リポジトリの明文方針（`.env`, `.env.*`）に忠実であることを、テンプレート閲覧の利便性より優先する。
3. **全プロジェクトに波及する。** `install.sh` が `settings.json` をユーザスコープへ同期するため、この deny は他のすべてのプロジェクトでも有効になる。ADR-0006 が負の帰結として記録した波及経路と同一のものが、逆向きに働く。

## 強制の到達範囲（`permissions.md` に明記すべき境界）

| 経路 | 塞がれるか |
|---|---|
| 組み込みファイルツール（Read / Edit / Write、Grep / Glob へのベストエフォート） | 塞がれる |
| Claude Code が認識する Bash ファイルコマンド（`cat`、`head`、`tail`、`sed`） | 塞がれる |
| 任意のサブプロセス（Python / Node スクリプトが自前で開く） | **塞がれない** |
| OS レベルの全プロセス | **塞がれない**（サンドボックス有効化が必要 — 本仕様のスコープ外） |

この境界を書かないことは、「方針だけあって強制がない」という ADR-0006 後の状態を、「強制があると誤認させる」形で反転させて繰り返すことになる。
