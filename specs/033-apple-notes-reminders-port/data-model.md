# データモデル: Apple Notes / Reminders 自動操作スキル

本機能はデータストアを自ら所有しない（`plan.md` Technical Context の Storage: N/A）。以下のエンティティは、Notes.app / Reminders.app 自身が保持するデータのうち、本機能のスクリプトが読み書きするフィールドの形を記述する — 独自のスキーマ設計ではなく、両アプリの既存プロパティ surface のドキュメント化である。

## Note（ノート）

Notes.app 上の1件のノート。`spec.md` FR-001〜FR-016 が操作対象とする主エンティティ。

| フィールド | 型 | 説明 | 出典/制約 |
|---|---|---|---|
| `id` | string | 安定したハンドル。形式 `x-coredata://<store>/ICNote/p<N>`。不透明な識別子として扱う。 | `research.md` 決定2（Script Editor 実機検査） |
| `name` | string | 導出値。**直接設定しない** — Notes は本文の1行目からタイトルを導出する。作成時に `name` を渡すと重複タイトル行が挿入される既知の不具合があるため、`write_note.js` は作成時に `body` のみを渡す。 | 移植元スキルの実機検証（specs/006 相当、本機能では再実装のみ・再検証はしない実装詳細） |
| `body` | string (HTML) | ノート本文。安全な Markdown サブセットから変換して生成するか、`--replace-block` で名前付き区画のみを差し替える。 | FR-004, FR-009, FR-012, FR-013 |
| `folder` (container) | Notes Folder への参照 | 所属フォルダ。 | FR-001 |
| `creation date` / `modification date` | datetime | 読み取り専用。 | — |

**状態遷移（上書き・削除）**: `spec.md` ユーザーストーリー4 / FR-014, FR-015 に対応。

```text
[読み取り済み] --(整合性トークン一致)--> [上書き成功 / 削除成功（復元可能な削除済み状態へ）]
[読み取り済み] --(整合性トークンが現在の内容と不一致)--> [拒否、内容変化なし]
```

整合性トークンは「直前に読み取った本文のプレーンテキストから計算した SHA-256 ハッシュ」（`note_write_guard.py` が計算・照合）。上書き／削除の実行前に、置き換え内容（または削除対象の識別情報）を人間に提示し明示的承認を得ることは、この状態遷移の外側にある運用上の前提条件であり、状態そのものには含まれない（FR-015、システムが自動チェックできる範囲ではないため）。

## Notes Folder（Notes フォルダ）

| フィールド | 型 | 説明 | 出典/制約 |
|---|---|---|---|
| `id` | string | フォルダの識別子。 | — |
| `name` | string | 完全一致で照合される名前。 | FR-001, FR-003 |
| `container` | account または親フォルダへの参照 | `--parent-id` 指定時は親フォルダの直下、未指定時は既定アカウント直下。 | FR-001 |

**「存在を保証」操作の遷移**（FR-001, FR-003）:

```text
[要求名に完全一致するフォルダが 0件] --> [1件作成、created: true]
[要求名に完全一致するフォルダが 1件] --> [その1件を再利用、created: false]
[要求名に完全一致するフォルダが 2件以上] --> [何も作成せず失敗]
```

## Reminder（リマインダー）

Reminders.app 上の1件のリマインダー。`spec.md` FR-005〜FR-011, FR-016 が操作対象とする主エンティティ。

| フィールド | 型 | 説明 | 出典/制約 |
|---|---|---|---|
| `id` (`calendarItemIdentifier`) | string | ローカル識別子。アカウント/カレンダー移動で永続しない場合がある。 | `research.md` 決定7 |
| `externalId` (`calendarItemExternalIdentifier`) | string | サーバー提供の識別子。`id` より安定だが、繰り返しアイテムでは一意性が保証されない。 | `research.md` 決定7 |
| `name` | string | 必須。 | FR-005 |
| `body` | string（自由記述） | 任意。EventKit の `notes` フィールドに対応。 | FR-005 |
| `completed` / `completionDate` | bool / datetime | `completionDate` は `completed` の切り替えに応じてフレームワークが自動設定・自動クリアする。呼び出し側が直接設定してはならない。 | FR-011, `research.md` 決定8 |
| `dueDate` | datetime（任意） | — | FR-005 |
| `priority` | int（任意） | — | — |
| `list` | Reminders List への参照 | 所属リスト。 | FR-002, FR-010 |

**削除**: 提供しない（FR-016）。よってこのエンティティに「削除済み」状態は存在しない — 完了/未完了の2状態のみ。

## Named Block（名前付き区画）

Note の `body` 内部に存在する、機械管理された部分構造。独立したエンティティではなく Note の内部構造だが、置換操作の対象単位として明示的にモデル化する（FR-009）。

| フィールド | 型 | 説明 |
|---|---|---|
| `name` | string | 区画を識別する名前。`--- <name> ---` … `---` の形式で本文内に区切られる。 |
| `content` | string | 区画内部のコンテンツ。区画外の地の文とは独立に読み書きされる。 |

**状態遷移**（FR-009）:

```text
[区画が存在しない] --(replace-block)--> [末尾に新規作成（追記）]
[区画がちょうど1つ存在] --(replace-block)--> [その区画のみ置換、区画外は不変]
[同名区画が2つ以上、または区切りが不正] --(replace-block)--> [拒否]
```
