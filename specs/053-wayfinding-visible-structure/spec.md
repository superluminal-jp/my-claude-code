# Feature Specification: 現在地の分かるスライドと、見て分かる文章構造

**Feature Branch**: `claude/digital-agency-slide-skill-vqe5ky`

**Created**: 2026-10-28

**Status**: Draft

**Input**: User description: "スライドのベストプラクティスとして今全体構造の中でどこにいるのかがわかりやすいように改善。文章構造が視覚的にもわかりやすいように工夫を取り入れる"

**Authority**: 本仕様が正である。直前の依頼(spec 052)が回答・文章・スライドのすべてを対象にしていたため、2文目は回答と文章にも適用する(確度: 中)。spec 051 の枚数の上限と spec 052 の部の順序は変えない。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - どのスライドでも、全体の中の現在地が分かる (Priority: P1)

聴き手や読み手は、表紙以外の本編のどのスライドを見ても、資料全体の構成(前提・結論・各論点・依頼)と、その中で今どこにいるかを一目で知る。

**Why this priority**: 利用者が挙げた第一の要望。構成を示すしるし(見出し、目次、現在地の強調)は、聞き手が内容の構成をつかむ助けになる(Mayer の信号化の原則)。

**Independent Test**: テンプレートの本編の各スライドに現在地の表示があり、現在の項目が言葉と太さと下線で示され、`lint` が表示と実際の位置の食い違いを報告する。

**Acceptance Scenarios**:

1. **Given** テンプレート、**When** 表紙と付録以外のスライドを見る、**Then** 右上に資料の構成(前提・結論・論点1〜3・依頼)が並び、そのスライドの項目が太字と下線で強調され、`aria-current="step"` を持つ。
2. **Given** テンプレート、**When** フッターを見る、**Then** 本編のスライドは「n / 全体」の番号を持つ。
3. **Given** 現在地の表示が実際の位置と食い違う、または項目数が本編(表紙を除く)の枚数と食い違うスライド、**When** `lint` を実行する、**Then** エラー `tracker` が出る。
4. **Given** ほかの本編スライドは現在地の表示を持つが、あるスライドだけ持たないデッキ、**When** `lint` を実行する、**Then** 警告 `tracker-missing` が出る。
5. **Given** どのスライドも現在地の表示を持たないデッキ、**When** `lint` を実行する、**Then** 現在地についての所見は出ない。

---

### User Story 2 - スライド上で論点の木の階層が見て分かる (Priority: P1)

読み手は、スライドの見た目だけで、主張(見出し)、それを支える子(ブロック)、子の中の根拠、全体の意味(帯)の階層を区別できる。

**Independent Test**: 設計の参照文書が、木の階層ごとの見た目(要素、大きさと太さ、まとまり方)を表で定める。

**Acceptance Scenarios**:

1. **Given** 設計の参照文書、**When** 読む、**Then** 現在地、節(見出し)、子、根拠、意味のそれぞれについて、使う要素と見た目の区別が定められている。
2. **Given** 同じ文書、**When** 読む、**Then** 結論スライドの木の番号と論点スライドの番号が一致すること、関係の近い要素ほど近くに置くことが書かれている。

---

### User Story 3 - 回答と文章でも構造が見て分かる (Priority: P2)

利用者が受け取る長い文章では見出しが木の位置で番号付けされ主張として書かれ、どの回答でも支える論点の主張が太字で先頭に置かれ、根拠がその下に入れ子になる。順序や比較は番号付きリストや表で示される。

**Independent Test**: 常時ロードの規則がこれらを定め、構造テストと容量の上限を満たす。Claude.ai 用プロンプトも同じ内容を持ち、7,000字以下である。

**Acceptance Scenarios**:

1. **Given** 読み手向け構造の規則、**When** 読む、**Then** 長い文章の見出しを木の位置で番号付けし主張として書くこと、支える論点の主張を太字で先頭に置き根拠を入れ子にすること、順序・順位は番号付きリスト、同じ基準での比較は表にすることが書かれている。
2. **Given** 規則層、**When** 構造テストを実行する、**Then** 5ファイルのまま、常時ロードの合計が基準値未満である。
3. **Given** Claude.ai 用プロンプト、**When** 文字数を数える、**Then** 記載と一致し、7,000字以下である。

### Edge Cases

- 表紙と付録は現在地の表示を持たない。付録のフッターは「付録 n」とする。
- 現在地の表示は色だけで現在を示さない(太字と下線と `aria-current`)。
- 短い回答では見出しを付けない(spec 052 のまま)。太字は支える論点の主張にだけ使い、装飾には使わない。

## Requirements *(mandatory)*

- **FR-001**: テンプレートは表紙と付録以外のスライドに現在地の表示(`ol.sld-tracker`)を持ち、本編のフッターは「n / 全体」を持たなければならない。
- **FR-002**: `lint` は User Story 1 の受け入れシナリオ3〜5のとおりに報告しなければならない。
- **FR-003**: 設計の参照文書は User Story 2 の内容を持ち、`deck-checks.md` は新しい所見のコードを持たなければならない。
- **FR-004**: 常時規則と Claude.ai 用プロンプトは User Story 3 の内容を持たなければならない。
- **FR-005**: README(英・日)は変更後の挙動と一致しなければならない。

## Success Criteria *(mandatory)*

- **SC-001**: 現在地の fixture で `tracker` と `tracker-missing` だけが報告される(fixture テスト)。
- **SC-002**: テンプレートは本編7枚、`lint` の所見0件のまま(E2E)。
- **SC-003**: 規則の構造テストが通り、常時ロードの合計が 20,126 バイト未満。Claude.ai 用ブロックは 7,000 字以下。

## Assumptions

- 2文目「文章構造が視覚的にも」は回答と文章にも適用する(確度: 中。直前の依頼の対象範囲から推定)。
- 現在地の表示はこのスキル独自の `sld-tracker` とする。DADS のステップナビゲーションは現在地を示す公式部品だが、各スライドに置くと約90px を占め本文の領域を圧迫する。`aria-current` で現在を示す方法は同部品にならう(確度: 中)。
