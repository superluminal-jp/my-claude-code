# Phase 1 データモデル: `product-strategy` スキル

**機能**: 037-product-strategy-skill | **日付**: 2026-09-04 | **計画**: [plan.md](./plan.md)

本機能には実行時のデータストアは存在しない。「モデル」とは、本リポジトリが保持する設定エンティティ（スキル自体）と、本スキルが利用先プロジェクトに生成する成果物（戦略ブリーフ）の構造、およびそれらに課される不変条件——構造契約テストや受け入れシナリオが検証するもの——である。

---

## エンティティ: スキル（`product-strategy`）

トリガーに一致した依頼に対して Claude Code がロードするオンデマンドの playbook。

| フィールド | 出所 | `product-strategy` での値 |
|---|---|---|
| `name` | `SKILL.md` フロントマター | `product-strategy` |
| `description` | `SKILL.md` フロントマター | トリガー条件と明示的な非対象条件（除外境界）の両方を1文で記述（FR-002、SKILL-03） |
| `when_to_use` | `SKILL.md` フロントマター | **存在しない**——`description` のみをトリガーメタデータとする（SKILL-02） |
| `allowed-tools` | `SKILL.md` フロントマター | **存在しない**——本スキルは追加のツール権限を要求しない |
| 本文 | `SKILL.md` | フレームワークの引用10件を含む本文。`references/` サブディレクトリなし（規模が本文内引用で完結するため） |

**検証ルール**

- V1. `name` は格納ディレクトリ名（`.claude/skills/product-strategy/`）と一致しなければならない。
- V2. `description` は、トリガーとなる語句・場面と、除外境界（`clarifier`・`scrum-master`・`minto-builder` との違い）の両方を含まなければならない（FR-002、FR-005、SKILL-03）。
- V3. 本文は `clarifier`・`scrum-master`・`minto-builder`・`coder` 等の他スキル名をそのまま埋め込んではならない（FR-017、SKILL-05 相当——サイバーリング参照の禁止）。
- V4. 本文中のすべての引用は、[参考文献](./spec.md#参考文献) に列挙された10件のいずれかに紐づかなければならない（FR-003）。
- V5. 本文はアーキテクチャ/技術スタックの意思決定を行う手順を含んではならない（FR-004）。
- V6. 本文は `.claude/skills/product-strategy/` 自身の配置先パスをハードコードしてはならない（FR-018、SKILL-06）。

## エンティティ: 戦略ブリーフ

`product-strategy` スキルの実行によって、対象プロジェクトに生成される単体の出力ドキュメント。本リポジトリの所有物ではなく、対象プロジェクトの所有物である（FR-011）。

| フィールド | 必須/任意 | 説明 |
|---|---|---|
| ステータスマーカー | 必須 | `完成` または `ドラフト（未完成）`。後者は FR-007a に基づき、引き出しセッションが中断された場合に付与される |
| 未回答セクション一覧 | ステータスが「ドラフト（未完成）」のときのみ必須 | どのセクションが未回答かを明示するリスト（FR-007a） |
| ビジョン/課題 | 完成ブリーフでは必須 | Business Model Canvas / Lean Canvas / *INSPIRED* に基づく整理（FR-003a、FR-006） |
| ターゲットユーザー | 完成ブリーフでは必須 | JTBD + Opportunity Solution Tree に基づく整理（FR-003b、FR-006） |
| 提供価値 | 完成ブリーフでは必須 | Value Proposition Design に基づく整理（FR-003c、FR-006） |
| 成功指標 | 完成ブリーフでは必須 | North Star 的な成果指標 + 補助指標、または Balanced Scorecard（FR-003d、FR-006） |
| スコープと優先順位 | 完成ブリーフでは必須 | MoSCoW（+ 任意で狩野モデル、FR-003e/g）による整理（FR-006） |
| 制約 | 完成ブリーフでは必須 | FR-006 |
| 未解決の前提 | 該当があれば必須 | `デフォルト` / `代替案` / `影響` の3項目を持つ（FR-006、`clarifier` テンプレートを流用） |
| 既存文脈との関係 | 既存プロジェクトかつ既存文脈がある場合のみ必須 | 「拡張する/狭める/置き換える」のいずれかを明示（FR-009） |

**検証ルール**

- V7. `完成` ステータスのブリーフは、上表の6必須セクション（ビジョン〜制約）をすべて含まなければならない（FR-006、SC-004）。
- V8. `ドラフト（未完成）` ステータスのブリーフは、必須セクションの充足を問われない代わりに、未回答セクション一覧を必ず含まなければならない（FR-007a、SC-004 の除外規定）。
- V9. いずれの値も、対象プロジェクト内に根拠が存在しない場合は「未解決の前提」として明示されなければならず、事実として断定してはならない（FR-007）。
- V10. 既存文脈と矛盾・縮小する内容を含む場合、その関係性を明示するフィールド（既存文脈との関係）を省略してはならない（FR-009）。

**状態遷移**

戦略ブリーフには2つの独立した状態軸がある:

1. **完成度**: `引き出し中` → `完成` または `引き出し中` → `ドラフト（未完成）`（中断時、FR-007a）。`ドラフト（未完成）` から `完成` への自動遷移はない——前提条件が明示するとおり、スキルは部分ブリーフを読み込んでセッションを再開することはしない。
2. **版数**: 同一の出力先に既存のブリーフが見つかった場合、`上書き確認待ち` という一時状態を経て、ユーザーの回答に応じて `上書き` または `新バージョン作成` のいずれかに解決する（FR-011a）。サイレントな自動遷移は存在しない。

## エンティティ: 既存プロダクトの文脈

対象プロジェクトが既に文書化しているプロダクトに関する情報源。読み込まれるが、スキルによって書き換えられることはない。

| ソース | 存在時の扱い |
|---|---|
| `README.md` | 読み込み、記載済みの事実は聞き直さない（FR-008） |
| `CLAUDE.md` | 同上 |
| 過去の戦略ブリーフ（本スキルが過去に生成したもの） | 同上。複数存在し矛盾する場合は最新のものを提示し優先順位をユーザーに確認する（FR-009a） |
| 過去の `specs/<N>-*` ディレクトリ | 同上 |

**検証ルール**

- V11. 上記いずれのソースも存在しない場合、スキルはインタビューのみの引き出しにフォールバックし、履歴の欠落をフラグとして示さなければならない（でっち上げてはならない、FR-010）。
- V12. 複数の情報源が矛盾する場合、スキルはどちらが優先するかをユーザーに確認しなければならない（FR-009a、サイレント統合の禁止）。
