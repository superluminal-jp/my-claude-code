# Contract: 検査報告

`secure-logging` が利用者に返す報告の形。レビューと実装のどちらでも、この順序と内容を守る。

## 順序

1. **結論**: 不合格の件数、未検証の件数、最も重大な不合格。
2. **項目別の判定**: チェックリストの順に、`id`、判定(Pass/Fail/N/A/Unverified)、根拠。
3. **実施した変更**(実装モードのみ): 変更の概要、先に書いた失敗するテスト、実行した検査とテストの結果。
4. **利用者が用意すべき証拠**: Unverified の項目ごとに、判断に必要な証拠。
5. **未検査の範囲**: 対象外にした場所と、実行できなかった検査。

## 規則

- Pass と Fail は `file:line` かテストを根拠として示す。
- N/A と Unverified は理由を示す。
- group B の項目は、リポジトリ内の設定が根拠になる場合を除き Pass にしない。
- 観測した事実、出典に基づく要件、推論を区別する。
- 対象が指定されなかった場合は、差分を優先し、無ければ全体とした旨を書く。
