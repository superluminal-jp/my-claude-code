# Phase 0 リサーチ: `problem-definition` スキルの追加

**日付**: 2026-09-05 | **仕様**: [spec.md](./spec.md) | **計画**: [plan.md](./plan.md)

`037-product-strategy-skill` の実装により、本リポジトリの現行メカニズム（構造契約テスト・配布・README ドキュメント）は既に一度、深く調査済みである（`specs/037-product-strategy-skill/research.md` D1〜D5）。本リサーチはそれを鵜呑みにせず直接再検証したうえで、本機能固有の論点——4つのフレームワークの適用範囲、および `product-strategy` を含む隣接スキルとのルーティング境界の言語設計——に絞って行う。

---

## D1. 現行メカニズムの再検証（`037`の D2/D3/D5 が引き続き有効であることの確認）

**決定**: `037`の research.md が確立した以下の事実は、直接再検証した結果、変更なく成立している。本機能もこれに従う。

- `tests/run-config-pyramid.sh` の `authored_skills` 配列（現在11件、`product-strategy` を含む）に `problem-definition` を追加すればよい。
- README のスキル一覧（`README.md`・`README.ja.md`）の対象ピア集合も同じ11件（`037`実装後の集合）である。
- `install.sh` はディレクトリ一括同期のため無編集で足りる。

**根拠**: `tests/run-config-pyramid.sh` の `authored_skills` 配列を直接 `grep` し、`product-strategy` が既に11件中の1件として存在することを確認した。`install.sh` の該当箇所は `037`実装時から変更されていない（git 履歴上、本機能着手までの間に別の変更は入っていない）。

**却下した代替案**: `037`の研究結果を再調査せず前提として流用する——却下理由: ドキュメントは執筆時点のスナップショットであり、その後の変更を見逃すリスクがある（本リポジトリ自身の `live-documentation.md` の原則）。実際に直接検証するコストは低く、再検証を省略する理由がない。

## D2. ルーティング境界の言語設計 — 隣接スキルを名指しせずに区別する

**決定**: `description` は、`clarifier`（既にスコープ確定した1機能の要件確定）・`product-strategy`（6セクションの戦略ブリーフの中の1ステップとしての問題整理）・`adr`（アーキテクチャ決定の文脈記述）のいずれとも異なる、「単体の問題文それ自体を生成物とする、汎用・ドメイン不問の引き出し」という一点で自らを区別する。兄弟スキル名は一切書かない（FR-016、`037`の SKILL-05 違反の教訓を最初から適用）。

**根拠**: `037`の実装過程で、SKILL.md 本文にうっかり `` `clarifier` `` と書いてしまい、`run-config-pyramid.sh` の SKILL-05 チェックに抵触しかけた（`037`の実装ログ）。本機能では同じ轍を踏まないよう、plan 段階で言語設計を先に決めておく。

**却下した代替案**: 「`product-strategy` の一部として使われることを想定した記述にする」——却下理由: spec.md の明確化決定#3（完全独立・相互参照なし）に反する。

## D3. フレームワーク適用の実装粒度

**決定**: spec.md の参考文献（Ishikawa、Kepner-Tregoe、BABOK、Shook/A3）は、4つの引き出し要素（現状・あるべき姿・ギャップ・重要性）それぞれに次のように対応づけて実装する:

| 要素 | 主たる出典 | 実装上の役割 |
|---|---|---|
| 現状 | BABOK（現状分析）、A3（現状条件） | 事実・データに基づく記述を促す |
| あるべき姿 | Ishikawa/QC（あるべき姿）、BABOK（将来状態）、A3（目標条件） | 期待値・標準を明確化させる |
| ギャップ（問題文そのもの） | Kepner-Tregoe（deviation）、A3（測定されたギャップ） | 現状とあるべき姿の対比として問題文を定式化させる |
| 重要性 | Kepner-Tregoe（「対応を要するほど重大か」という判定基準） | なぜ今取り組む必要があるかを明示させる |

**根拠**: spec.md の参考文献セクションに列挙済みの各出典が、それぞれどの要素に最も強く対応するかを整理した。

**却下した代替案**: 4出典すべてを4要素すべてに一律で紐づける——却下理由: `037`の FR-003a〜g の precedent（各出典を最も強く関連するセクションに絞って紐づける）と整合させ、引用の希薄化を避けるため。
