# Feature Specification: 論文の構成とミント・ピラミッドの統合

**Feature Branch**: `claude/digital-agency-slide-skill-vqe5ky`

**Created**: 2026-10-28

**Status**: Draft

**Input**: User description: "一般的な論文の文章構成をミントピラミッドと合わせて採用する。スライド構成にも文章作成にも回答にも。" 確認のうえ、既定案3点で合意した: (1) 論文の構成は IMRaD(序論・方法・結果・考察)と冒頭の構造化要旨、(2) スライドでは方法を前提スライドに、限界を依頼スライドに1行ずつ入れ、本編の上限 k + 4 枚を保つ、(3) 部の見出しは長い文章にだけ付け、通常の回答は見出しなしで同じ順に並べる。

**Authority**: 本仕様が正である。spec 051 で定めた「結論先行」「前提と用語」「スライドの枚数の上限」は保ち、その上に部の順序を加える。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 回答と文章が「要旨 → 前提 → 方法 → 結果 → 考察 → 結論」の順に並ぶ (Priority: P1)

利用者が分析・説明・報告などの実質的な回答や文章を求める。結果は、結論と主な根拠を最初に述べ、続いて前提(背景・問題・問い・用語)、根拠の得方(情報源・手順・前提条件)、論点ごとの根拠、解釈と限界、次の行動の順に並ぶ。各段落は最初の文で主張を述べる。

**Why this priority**: すべての回答と文章に効く常時の規則であり、利用者が根拠の信頼性と限界を判断できるようにする。

**Independent Test**: 常時ロードの規則が部の順序・空の部の省略・見出しの条件・段落の先頭文を定め、規則層の構造テストが通る。

**Acceptance Scenarios**:

1. **Given** 読み手向け構造の規則、**When** 読む、**Then** 6つの部(要旨、前提、方法、結果、考察、結論)がこの順で定義され、結論先行が保たれている。
2. **Given** 同じ規則、**When** 読む、**Then** 中身の無い部は省き、短い回答では同じ順で数文に縮めることが書かれている。
3. **Given** 同じ規則、**When** 読む、**Then** 部を見出しとして出すのは報告書・分析・文書などの長い文章だけで、通常の回答は見出しなしで同じ順に並べることが書かれている。
4. **Given** 同じ規則、**When** 読む、**Then** 各段落が最初の文で主張を述べることが書かれている。
5. **Given** 規則層、**When** 構造テストを実行する、**Then** 規則は5ファイルのまま、相互参照が無く、常時ロードの合計が基準値未満である。

---

### User Story 2 - スライドにも同じ部が対応し、枚数は増えない (Priority: P1)

資料の作成者がスライドを頼む。デッキの各スライドは論文の部に対応し、方法は前提スライドに、限界は依頼スライドに1行ずつ入る。本編の上限は k + 4 枚のままである。

**Why this priority**: 枚数を抑える直前の改善(spec 051)と両立させる必要がある。

**Independent Test**: 設計の参照文書が部とスライドの対応を定め、テンプレートの前提スライドに方法の行、依頼スライドに限界の行があり、テンプレートの本編が7枚のまま `lint` の所見が0件である。

**Acceptance Scenarios**:

1. **Given** 設計の参照文書、**When** 読む、**Then** 要旨=表紙と結論スライド、序論=前提スライド、方法=前提スライドの1行、結果=論点スライド、考察=依頼スライドの限界の1行、結論=依頼スライド、付録=付録スライド、の対応が書かれている。
2. **Given** 同梱テンプレート、**When** 前提スライドを読む、**Then** 根拠の得方(調べ方)を述べる1行がある。
3. **Given** 同梱テンプレート、**When** 依頼スライドを読む、**Then** 結論の限界を述べる1行がある。
4. **Given** 同梱テンプレート、**When** 公式資材を取得して `lint` を実行する、**Then** 本編は7枚、所見は0件である。

---

### User Story 3 - Claude.ai でも同じ順序で答える (Priority: P2)

利用者が Claude.ai で回答を受け取るときも、同じ部の順序が適用される。

**Independent Test**: Claude.ai 用の移植プロンプトが部の順序を持ち、記載の文字数が実数と一致し、自主上限(約7,000字)以内である。

**Acceptance Scenarios**:

1. **Given** Claude.ai 用の移植プロンプト、**When** 読む、**Then** 部の順序、空の部の省略、見出しの条件、段落の先頭文が書かれている。
2. **Given** 同じプロンプト、**When** ブロックの文字数を数える、**Then** 記載の値と一致し、7,000字以下である。

### Edge Cases

- 一つの事実を問う質問や短い直接の答えには、部の構造を持ち込まない(既存の Scope のとおり)。
- 方法が「質問文から推論しただけ」の場合は、その旨を一文で書く。
- 結論の部は要旨の繰り返しではなく、次の行動・判断として書く。
- ChatGPT 用の移植プロンプトは対象外(文字数の上限)。外部から取り込んだ `minto-pyramid` スキルは編集しない。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 読み手向け構造の規則は、User Story 1 の受け入れシナリオ1〜4の内容を持たなければならない。
- **FR-002**: スライドの設計の参照文書は、User Story 2 の受け入れシナリオ1の対応を持たなければならない。
- **FR-003**: テンプレートは前提スライドに方法の行を、依頼スライドに限界の行を持ち、本編7枚・所見0件を保たなければならない。
- **FR-004**: Claude.ai 用の移植プロンプトは部の順序を持ち、文字数の記載を更新しなければならない。
- **FR-005**: README(英・日)の規則とスライドスキルの説明は、変更後の挙動と一致しなければならない。

## Success Criteria *(mandatory)*

- **SC-001**: 規則の所有権の検査(部の順序、段落の先頭文)が構造テストで通る。
- **SC-002**: スライドの契約テストで、部とスライドの対応、テンプレートの方法の行と限界の行が確認され、E2E で本編7枚・所見0件が確認される。
- **SC-003**: Claude.ai 用プロンプトのブロックは7,000字以下。

## Assumptions

- 「一般的な論文の構成」は IMRaD と冒頭の構造化要旨とする(利用者が既定案で合意)。
- 部の名前(要旨・方法など)は長い文章の見出しにだけ使う。IMRaD などの枠組みの名前は出力に書かない。
