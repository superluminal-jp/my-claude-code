# Feature Specification: HTML専用のDADSスライドと、初学者が追える説明

**Feature Branch**: `claude/digital-agency-slide-skill-vqe5ky`

**Created**: 2026-10-28

**Status**: Draft

**Input**: User description: "Digital Agency Slide Skill でpptxへの変換は全く使わないことがわかったのでpptxへの変換可能性は排除してHTMLで完全にデジタル庁デザインガイドに準拠するように改善。また、一枚の内容を簡潔に短くするためにスライド枚数が多くoverwhelming になる傾向があるのでミントピラミッド原理に従って前提形成から結論先行してツリー構造で展開することを念頭において構成するような改善も行いたい。また全体的なClaudeの回答として専門性が高い内容について回答する際にユーザーがついていけないことが多いので各トピックについて初心者初学者にとってもわかりやすいような表現や前提や定義の提示などを行うようにしたい。他のもので例える比喩は物事の一側面しか反映せず誤解の元になるので絶対に行わない。"

**Authority**: 本仕様が正である。現行の `digital-agency-slides` は PowerPoint 変換を前提に設計面を固定しているが、その前提は利用実態と合わないことが利用者により確認された。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - デッキが「前提 → 結論 → 論点の木」で組まれ、枚数が抑えられる (Priority: P1)

資料の作成者がスライドの作成を頼む。結果として受け取るデッキは、聞き手が共有すべき前提(状況・問題・用語の定義)を最初に示し、次に結論とそれを支える論点の一覧を1枚で示し、論点ごとに1枚ずつ根拠を示す。1つの根拠のためにスライドを増やさない。

**Why this priority**: 枚数が多すぎて聞き手が全体を追えなくなることが、利用者が挙げた直接の問題である。

**Independent Test**: 同梱テンプレートと、構成規則に反する小さなデッキに `lint` を実行し、構成に関する警告が規則どおりに出ること、テンプレートでは警告が出ないことを確かめる。

**Acceptance Scenarios**:

1. **Given** 結論を支える論点が k 個(2〜4、最大5)、**When** スキルに従ってデッキを計画する、**Then** 本編は表紙・前提・結論・論点 k 枚・依頼(任意)からなり、枚数は k + 4 以下である。論点を支える根拠はその論点のスライドに載り、独立したスライドにならない。
2. **Given** 付録を除く本編が9枚を超えるデッキ、**When** `lint` を実行する、**Then** 警告 `deck-long` が出る。
3. **Given** 結論スライド(`data-layout="answer"`)が無い、または4枚目以降にあるデッキ、**When** `lint` を実行する、**Then** 警告 `late-answer` が出る。
4. **Given** 付録スライドの後に本編のスライドが続くデッキ、**When** `lint` を実行する、**Then** 警告 `appendix-order` が出る。
5. **Given** 同梱テンプレート、**When** 公式資材を取得して `lint` を実行する、**Then** 本編は7枚、結論スライドは3枚目で、エラーも警告も0件である。

---

### User Story 2 - デッキはHTMLだけで完結し、DADSに準拠する (Priority: P1)

資料の作成者が受け取るのは1つのHTMLデッキである。PowerPointへの変換手段・依存・制約は含まれない。デッキはデジタル庁デザインシステム(DADS)の公式コンポーネントを公開どおりのマークアップで使い、ウェブ文書としてDADSのアクセシビリティ要件を満たす。

**Why this priority**: 変換を前提とした制約(擬似要素の禁止、`data-pptx`、px/pt/EMUの換算)がHTMLとしての準拠を妨げていた。変換を使わない以上、これらは不要な複雑さである。

**Independent Test**: スキルのパッケージに変換の痕跡が無いこと、テンプレートが公式コンポーネントを使うこと、規則に反するHTMLに対して `lint` が該当するエラーを出すことを確かめる。

**Acceptance Scenarios**:

1. **Given** スキルのパッケージ、**When** 内容を調べる、**Then** `.pptx` を生成するコマンド、`python-pptx` への依存、変換の参照文書、`data-pptx` 属性が無く、説明文は `.pptx` の作成・編集を対象外と明記する。
2. **Given** 同梱テンプレート、**When** マークアップを調べる、**Then** スライドの見出しはDADSの見出しコンポーネント(`hgroup.dads-heading` とショルダー)、用語の定義は説明リスト、列挙は箇条書きリスト、表は表コンポーネント、出典はリンクコンポーネントを公開どおりに使い、`sld-*` はスライドの寸法とDADSに無いブロックにだけ使われる。
3. **Given** 次のいずれかを含むHTML — `lang` の無い `<html>`、空の `<title>`、`h1` が1つでない文書、見出しレベルの飛び越し、見出しの無いスライド、`alt` の無い画像、アクセシブルな名前の無い `svg`、`<th>` の無い表、4.5:1 未満の文字コントラスト、14px 未満の文字、スライドからはみ出す内容、切れる文字、大きさの異なるスライド — **When** `lint` を実行する、**Then** それぞれ対応するエラーが出て、終了コードが0でない。
4. **Given** 同梱テンプレートを複製したデッキ、**When** ブラウザで印刷する、**Then** 1スライドが1280x720の1ページになる(既存の `@page` 規則)。

### User Story 3 - 専門的な回答を初学者が追える (Priority: P2)

利用者が専門性の高い内容を尋ねる。回答は、結論が依存する前提を示し、専門用語・略語を初出で平易に定義し、比喩や類推で説明しない。説明は対象そのもの(定義、構成要素、関係、対象自体の具体例)で行う。

**Why this priority**: 回答の内容が正しくても、利用者が前提や用語を知らなければ判断に使えない。常時適用の規則であるため全セッションに影響する。

**Independent Test**: 常時ロードの規則が上記の義務を持ち、規則層の構造テスト(5ファイル、横参照なし、容量上限)が通ること、Claude.ai 用の移植プロンプトが同じ義務を持ち文字数の記載が実数と一致することを確かめる。

**Acceptance Scenarios**:

1. **Given** 読み手向け構造の規則、**When** 読む、**Then** 前提の提示、初出の用語の平易な定義、比喩・類推の禁止(理由つき)、対象自体の具体例は比喩ではないこと、が書かれている。
2. **Given** 規則層、**When** 構造テストを実行する、**Then** 規則は5ファイルのまま、相互参照が無く、常時ロードの合計が基準値未満である。
3. **Given** Claude.ai 用の移植プロンプト、**When** 読む、**Then** 同じ義務を持ち、記載の文字数が実際のブロックの文字数と一致し、自主上限(約7,000字)以内である。
4. **Given** スライドスキル、**When** 前提スライドの指針を読む、**Then** 聞き手が知らない用語を平易に定義し、比喩で説明しないことが書かれている。

---

### Edge Cases

- 聞き手が前提をすでに共有している場合、前提スライドは省ける。結論スライドは3枚目以内のままである。
- 何も依頼しない報告のデッキでは、依頼スライドを省ける。
- 論点が1つしかない場合は木にならない。結論スライドの本文に根拠を直接載せる。
- 論点が5つを超える場合は、スライドを分けるのではなく論点を4つ以下にまとめ直す。
- 付録は本編の枚数に数えない。付録は本編の後にだけ置く。
- ChatGPT 用の移植プロンプトは対象外とする。全文ブロックが4,974字で上限5,000字に近く、追記できない。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: スキルはPowerPoint変換の手段・依存・参照文書・マークアップ上の指示を持ってはならない。説明文は `.pptx` の作成・編集を対象外としなければならない。
- **FR-002**: スキルは、本編を表紙・前提・結論・論点・依頼で構成し、スライドを木の節(主張とその直接の子)に対応させ、根拠を親のスライドに載せる構成手順を定めなければならない。
- **FR-003**: `lint` は構成について `deck-long`(本編が既定9枚を超える)、`late-answer`(結論スライドが無い、または4枚目以降)、`appendix-order`(付録の後に本編)を警告しなければならない。上限は `--max-slides` で変えられる。
- **FR-004**: テンプレートとマークアップの規約は、DADSの見出し・箇条書きリスト・説明リスト・表・リンク・チップラベルを公開どおりに使い、`sld-*` をスライドの寸法とDADSに無いブロックに限定しなければならない。
- **FR-005**: `lint` は User Story 2 の受け入れシナリオ3の各条件をエラーとして報告しなければならない。
- **FR-006**: スキルは `lint`(検査)と `preview`(スライドごとのPNG)を提供し、両者の依存は Playwright だけとする。
- **FR-007**: 常時ロードの読み手向け構造の規則は、User Story 3 の受け入れシナリオ1の義務を持たなければならない。
- **FR-008**: Claude.ai 用の移植プロンプトは同じ義務を持ち、文字数の記載を更新しなければならない。
- **FR-009**: README(英・日)、設計記録、テストは変更後の挙動と一致しなければならない。

### Key Entities

- **論点の木(Pyramid)**: 結論(根)、それを直接支える論点(第1層、2〜4個)、各論点の根拠(第2層)。
- **スライドの役割(`data-layout`)**: `title`、`premise`、`answer`、`point`、`closing`、`appendix`。木の中の位置を表す。
- **本文の型**: 箇条書き、数値タイル、比較、手順、表、図、定義。根拠の見せ方を表し、役割とは独立に選ぶ。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: テンプレートの本編は7枚(旧テンプレートは9枚)、結論は3枚目にあり、`lint` のエラー・警告は0件(E2Eテストで確認)。
- **SC-002**: 構成と文書の規則に反する試験用デッキで、FR-003 と FR-005 の各コードが報告される(fixtureテストで確認)。
- **SC-003**: スキルのパッケージ内で `pptx` の語が現れるのは `SKILL.md` の説明文の対象外の記述だけである(契約テストで確認)。
- **SC-004**: 規則層の構造テストが通り、新しい所有権の検査(初学者向けの説明と比喩の禁止)が通る。

## Assumptions

- 検査とプレビューの道具(Python と Playwright)は残す。DADSへの準拠を機械的に確かめる唯一の手段であるため(確度: 高)。
- 区切りスライド(`section`)と目次スライドは廃止する。結論スライドの木が目次を兼ねる(確度: 中)。
- 表紙は白地とし、DADSの見出しコンポーネントを上書きせずに使う(確度: 中)。
- 発表者メモはHTML内に非表示で残す。表示する仕組みは作らない(確度: 中)。
- 初学者向けの義務は既存の読み手向け構造の規則に加える。規則ファイルは増やさない(確度: 高)。
