# Data Model: 空の「不要」理由を弾く(S3)

永続データは無い。以下はゲートが最終メッセージから取り出す値の定義。

## Reason(理由)

| 項目 | 内容 |
|---|---|
| 由来 | 不要宣言、または `No change needed:` 行の、区切りより後ろの文字列 |
| 正規化 | NFKC → 大文字小文字の畳み込み → `<…>` の除去 → 強調記号(`*`、`_`、`` ` ``)の除去 → 両端の空白・句読点・記号(Unicode カテゴリ P*/S*/Z*)の除去 |
| 無効(boilerplate) | 正規化後が空、英数字・かなを 1 文字も含まない、または固定の一覧に一致 |
| 有効 | 上記以外(長さの下限なし) |

固定の一覧(正規化後の形): `n/a`、`na`、`none`、`nil`、`no`、`nothing`、`no impact`、`no change`、`no changes`、`no change needed`、`not applicable`、`no documentation impact`、`なし`、`無し`、`該当なし`、`変更なし`、`影響なし`、`特になし`。

## NoneDeclaration(不要宣言)

| 項目 | 内容 |
|---|---|
| 位置 | 行頭(空白、`>`、`-`、`*`、`•`、`_`、`#` の接頭辞を許す) |
| 形 | `Documentation impact` + 任意のコロン + `none` + 区切り + 理由 |
| 区切り | `—`、`–`、`-`、`:`、`：`(続く空白は無視)。区切りが無ければ理由は空文字列 |
| 検証 | 理由が有効か |

## Evidence(根拠)

| 種別 | 行の形 | 有効条件 |
|---|---|---|
| 更新 | `Updated: <内容>` | 内容(`<…>` のテンプレート表記を除く)に英数字・かながある |
| 変更不要 | `No change needed: <対象> — <理由>` | 理由が有効。区切りが無ければ行全体を理由とする |
| 不要宣言 | `Documentation impact: none — <理由>` | 理由が有効 |

## ReportCheck(検査の入出力)

| 入力 | 内容 |
|---|---|
| `message` | 最終メッセージ(無ければ検査しない) |
| `needs_report` | 既存の報告必須の分類のうち、変更に含まれるもの |
| `docs_changed` | 変更に `documentation` の分類が含まれるか |

| 出力 | 条件 |
|---|---|
| 問題 A | 無効な不要宣言が 1 つ以上ある(`docs_changed` を問わない) |
| 問題 B | `needs_report` が非空、見出しがある、`docs_changed` が偽、不要宣言が 0 件、かつ有効な根拠が無い |
| 空 | 上記以外 |

状態遷移は無い(ブロック回数などは既存の `on_stop` が管理)。
