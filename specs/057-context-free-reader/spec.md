# Feature Specification: 会話・コード・文書を見ていない読み手にも、語の指す先が分かるように書く

**Feature Branch**: `feat/context-free-reader`

**Created**: 2026-11-03

**Status**: Draft

**Input**: User description: "回答や成果物について、元のコードや文書・会話の経緯を知らないAIレビュアーが確認しても問題なく内容を把握できるようにすることで、定義が曖昧な言葉や多義的な言葉（「環境」「アカウント」など）が何を指しているか人がわかるようにしたい"

**利用者への確認と回答**: 実装の前に Claude が3つの質問をし、利用者は次のように答えた。

| # | 質問 | 選択肢 | 利用者の回答 |
|---|---|---|---|
| Q1 | 常時ロード(下の「用語」を参照)の容量の上限を、新しい義務のためにどう扱うか | 上限を引き上げる / 既存の文を同じ意味のまま短くして収める / 常時ロードには入れず `pyramid-structure` スキルにだけ入れる | 既存の文を短くして収める |
| Q2 | 既存の例外「利用者が既に正しく使った用語は定義を省いてよい」をどうするか | 例外を外す / 例外を残す | 例外を外す |
| Q3 | 「文脈を知らない AI レビュアー」を、書くときの基準として使うだけにするか、実際に動かすか | 基準として書くだけ(Claude が自分で点検する) / 文書や PR 本文などの成果物に限り、実際にサブエージェントに読ませる | 成果物に限り、実際に読ませる |

**Authority**: 本仕様(この `spec.md`)が正である。spec 051(`specs/051-html-slides-plain-explanations/`、初学者向けの前提と用語の定義を常時ロードのルールに加えた変更)が `.claude/rules/pyramid-principle.md` に加えた例外の文「Skip the definition only for a term the user has already used correctly」を、Q2 の回答に従って削除する。spec 056(`specs/056-term-form-follows-field/`、用語の形をその分野で決め、訳語を作らないことにした変更)は、その Edge Cases で「用語に定義を付けるかどうかは、従来どおり読み手で決める」とし、この例外の文を変えないと定めていたが、Q2 の回答で上書きする。spec 056 のほかの義務(用語はその分野の実務者が使う形で書き、訳語を作らないこと)と、読み手の知識水準を利用者の発言で調整する文「unless the user's own messages show otherwise」は変えない。

## 用語

- **常時ロード**: Claude Code がすべてのセッションの開始時に必ず読み込む設定ファイル。このリポジトリでは `.claude/CLAUDE.md` と `.claude/rules/` の5つのファイルで、`install.sh` が利用者のホームディレクトリの `~/.claude/` に同期する。毎回読み込まれるため、大きさを `tests/run-config-pyramid.sh` の検査 BUDGET-01 が制限している。
- **基準値 20,126 バイト**: BUDGET-01 が常時ロードの合計に課す上限(合計がこの値未満であること)。検査の名前は「unconditional corpus is smaller than legacy baseline」である。基準値は、spec 036(`specs/036-rule-layer-independence/`)でこの検査を加えたときに定めた値で、本仕様では変えない。
- **ルール**: `.claude/rules/` の Markdown ファイル。常時ロードされ、Claude の判断を変える指示だけを持つ。本仕様で変えるのは、読み手に向けた文章の組み立て方を定める `.claude/rules/pyramid-principle.md` である。
- **スキル**: `.claude/skills/<名前>/SKILL.md` に置く手順書。Claude が作業に関係すると判断したときだけ本文を読み込む。`pyramid-structure` スキルは、実質的な回答と文書をピラミッド構造(結論を先に置き、それを支える論点を下に並べる構成)で組み、送る前に検査する手順書である。
- **回答と成果物**: 回答は、会話の中で利用者に返す文章。成果物は、会話の外で読まれる文章で、人向けに書いた文書やファイル、仕様、報告、スライド、PR や issue の本文、公開ページを指す。コミットメッセージは成果物に含めない(Assumptions を参照)。
- **多義語と指示語**: 多義語は、複数のものを指しうる語(例: 「環境」はデプロイ先の AWS アカウント、ローカルの Python 仮想環境、環境変数のどれも指しうる)。指示語は、会話・コード・文書の中のものを指す語(例: 「そのファイル」「案B」「先ほどの修正」)。
- **サブエージェントと fork**: サブエージェントは、Claude Code が作業の一部を任せるために起動する別の Claude である。fork は、現在の会話の内容を引き継いで起動するサブエージェントを指す。本仕様の読み手役には、会話を引き継がない新しいサブエージェントを使う。
- **持ち運び用プロンプト**: このリポジトリの設定の原則を、Claude.ai と ChatGPT のカスタム指示欄に貼れる形にまとめた2つのファイル(`claude-ai-system-prompt.md`、`chatgpt-system-prompt.md`)。各ファイルの「ブロック」は、欄に貼るコードブロックを指す。`claude-ai-system-prompt.md` のブロックは1つで、Claude.ai の「Instructions for Claude」欄に貼る。`chatgpt-system-prompt.md` のブロックは3つで、「Custom instructions」欄に貼る全文(Plus 以上の有料プラン向け)と簡易(無料プラン向け)、および「More about you」欄に貼るものである。各ファイルの冒頭に、ブロックごとの文字数が書かれている(以下「記載の文字数」)。`install.sh` はこれらを同期しない。

## 背景

Claude の回答や成果物には、会話の中でしか指す先が決まらない多義語や指示語が残ることがある。会話を見ていない読み手、たとえば後から PR を読む人や、文脈を渡されていない AI レビュアーは、これらが何を指すかを決められない。

変更前(`origin/main` のコミット 3a8fece)の `.claude/rules/pyramid-principle.md` は、初学者(その分野を初めて学ぶ読み手)が知らない用語を初出で定義するよう求めていた。しかし次の2点が足りなかった。

1. 語の意味は分かっても、指す先が会話で決まる場合を扱っていなかった。
2. 利用者が使った用語は定義を省いてよいとしていた。このため、会話を見ていない読み手には、定義のない用語が残った。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - どの回答でも、多義語と指示語が何を指すかが書かれている (Priority: P1)

利用者が Claude Code に作業を頼み、回答や成果物を受け取る。会話・コード・文書を見ていない読み手がそれを読んでも、多義語がどれを指すか、指示語が何を指すかが本文だけから分かる。用語は、利用者が会話で使ったものでも、初学者が知らなければ初出で定義される。

**Why this priority**: 回答と成果物は会話の外でも読まれる(PR のレビュー、後日の読み返し、文脈を渡されていない AI レビュアー)。義務を常時ロードのルールに置けば、`pyramid-structure` スキルが読み込まれない短い回答にも効く。

**Independent Test**: `.claude/rules/pyramid-principle.md` が下記の義務を持つことと、`tests/run-config-pyramid.sh` の検査 RULE-01〜RULE-23 と BUDGET-01 が通ることを確かめる。これらは、`.claude/rules/` のファイルが5つであること、ルールがほかのルールのファイル名を書かないこと、各ルールが持つべき義務の文があること、常時ロードの合計が基準値未満であることを検査する。

**Acceptance Scenarios**:

1. **Given** `.claude/rules/pyramid-principle.md`、**When** 読む、**Then** 次の3つが書かれている。読み手は会話・コード・文書を見ていないと想定すること。複数の指す先を持つ語がどれを指すかを書くこと(例: どの環境、どのアカウント)。見えない文脈への指示語が何を指すかを書くこと(例: そのファイル、案B、先ほどの修正)。
2. **Given** 同じファイル、**When** 読む、**Then** 例外の文「Skip the definition only for a term the user has already used correctly」がない。
3. **Given** `.claude/rules/`、**When** `tests/run-config-pyramid.sh` を実行する、**Then** ルールは5ファイルのまま、ほかのルールのファイル名を書かず、常時ロードの合計が基準値 20,126 バイト未満である。基準値は変えない(Q1 の回答)。

---

### User Story 2 - 成果物は、会話を見ていないサブエージェントに読ませてから渡される (Priority: P1)

Claude は成果物を作ったら、渡す前に、会話を引き継がない新しいサブエージェントにその成果物だけを読ませる(Q3 の回答)。サブエージェントは、指す先が分からない語と、追えない文を引用して挙げる。Claude はそれを成果物の中で直す。挙がった項目があれば一度だけ読み直させ、なお残る項目を報告する。

**Why this priority**: 書き手が自分の持つ文脈を切り離して読み返すのは難しい。文脈を持たない読み手に実際に読ませれば、書き手の自己点検では残る語を見つけられる。費用と時間が増えるため、対象は成果物に限る。

**Independent Test**: `pyramid-structure` スキルの `SKILL.md` にある「Before sending any substantive output」節(実質的な出力を送る前に行う検査の手順)が下記を定めていることを、`tests/run-config-pyramid.sh` で確かめる。実際にサブエージェントが起動されるかという挙動は、本仕様では測らない(Assumptions を参照)。

**Acceptance Scenarios**:

1. **Given** 「Before sending any substantive output」節、**When** 読む、**Then** 次が書かれている。成果物の範囲(「用語」の定義と同じ)。会話での回答とコミットメッセージは対象外であること。fork ではない新しいサブエージェントに成果物だけを渡し、ほかのファイルを開かせないこと。指す先が分からない語と追えない文を引用させること。成果物の中で直すこと。読み直しは1回までであること。サブエージェントを起動する道具がなければこの手順を省き、省いたと伝えること。
2. **Given** 同じ節の完了チェック(送る前に確かめる項目の一覧)、**When** 読む、**Then** 「会話・コード・文書を見ていない読み手が、各語と指示語の指す先を分かる」ことが含まれている。

---

### User Story 3 - 持ち運び用プロンプトも同じ書き方の義務を持つ (Priority: P2)

持ち運び用プロンプトも、User Story 1 の受け入れシナリオ1の義務(読み手の想定と、多義語と指示語の明示)を持つ。User Story 2 のサブエージェントに読ませる手順は、Claude.ai と ChatGPT の会話にサブエージェントを起動する道具がないため移さない。

**Acceptance Scenarios**:

1. **Given** `claude-ai-system-prompt.md` のブロック、**When** 読む、**Then** 同じ義務を持ち、例外を表す句「(unless I used them)」がなく、記載の文字数が実際の文字数と一致し、このリポジトリが自分で決めた上限(約7,000字。Anthropic は上限を公表していない)以内である。
2. **Given** `chatgpt-system-prompt.md` の「More about you」(ChatGPT の設定画面にある欄の名前)に貼るブロック、**When** 読む、**Then** 同じ義務を持ち、記載の文字数が実際の文字数と一致する。
3. **Given** 両ファイルの「Not ported from `.claude/`」の表(移していない設定とその理由の一覧)、**When** 読む、**Then** サブエージェントに読ませる手順を移していないことが書かれている。

---

### Edge Cases

- 同じ出力の中で先に明示した語を、後から「上記の」で指すのはよい。明示が要るのは、会話・コード・文書の中でしか決まらない指す先である。
- 読み手の知識水準は、従来どおり利用者の発言で調整する。調整されるのは分野の一般知識であり、会話の中でしか決まらない指す先は常に明示する。
- 成果物を続けて複数作る作業では、成果物ごとに読ませる。
- サブエージェントが挙げた語のうち、利用者しか知らない情報がないと直せないものは、推測で埋めず、残った項目として報告する。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: `.claude/rules/pyramid-principle.md` は User Story 1 の受け入れシナリオ1の義務を持ち、受け入れシナリオ2の例外の文を持ってはならない。
- **FR-002**: FR-001 を満たしたうえで、常時ロードの合計を基準値 20,126 バイト未満に保つ。短くするのは、Claude の振る舞いを指示する文ではなく、同じファイルの末尾の「References」節にある参考文献の書誌表記(書名の副題、長い正式名、共著者の列挙)とする。
- **FR-003**: `pyramid-structure` スキルは User Story 2 の受け入れシナリオ1・2の手順を持つ。スキルの説明書 `.claude/skills/pyramid-structure/README.md` と、プラグインとしての定義 `.claude/skills/pyramid-structure/.claude-plugin/plugin.json`(説明と版)にも、User Story 2 の手順を加える。
- **FR-004**: `tests/run-config-pyramid.sh` は、FR-001 の義務(読み手の想定、多義語、指示語、例外の文がないこと)と、FR-003 のサブエージェントの手順を検査する。
- **FR-005**: 持ち運び用プロンプトは User Story 3 を満たす。`claude-ai-system-prompt.md` は約7,000字に収めるため、ブロックの中でほかの行と意味が重複する記述を削る。削った箇所は `tasks.md` の T005 に記録する。
- **FR-006**: `README.md` と `README.ja.md` の設定の要約、および `docs/claude-config-design.md` の「置いていないもの」の表(常時ロードの各ファイルが意図的に持たない内容と、その置き場所の一覧)を、変更後の内容に合わせる。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: `tests/run-config-pyramid.sh` が新しい検査を含めてすべて通る。新しい検査は、変更前に失敗することを確かめる。
- **SC-002**: 常時ロードの合計が 20,126 バイト未満である。
- **SC-003**: `claude-ai-system-prompt.md` のブロックが 7,000 字以下で、記載の文字数と一致する。`chatgpt-system-prompt.md` の各ブロックの文字数が記載と一致する。
- **SC-004**: `pyramid-structure` スキルの単体テスト(`.claude/skills/pyramid-structure/tests/`。検査スクリプトとプラグイン定義、評価ケースの形を検査する)が通る。

## Assumptions

各項目の確度は、その仮定が利用者の意図に合っている見込みを高・中・低で示す。

- 成果物にコミットメッセージは含めない(確度: 中)。Q3 で利用者が選んだ選択肢の説明は「文書や PR 本文などの成果物に限り」だった。コミットは回数が多く、1件ごとにサブエージェントを起動すると費用と時間が大きい。
- 「AIレビュアー」は、書くときの基準(会話・コード・文書を見ていない読み手)であり、成果物については実際に起動する読み手でもある(Q3 の回答)。
- 「unless the user's own messages show otherwise」は残す(確度: 中)。Q2 で利用者が外すと答えたのは「利用者が使った用語の定義を省く」例外であり、分野の知識水準の調整ではない。
- サブエージェントのモデルと労力(推論にかける量)は、スキルの中で固定しない。常時ロードのルール `.claude/rules/model-routing.md` に従い、確実にこなせる範囲で最も低い能力のモデルと労力を、起動のたびに選ぶ。
- 挙動(実際にサブエージェントに読ませるか、指す先の分からない語が減るか)は本仕様では測らない。測るには、`.claude/skills/pyramid-structure/evals/` に、成果物を作らせてサブエージェントが起動されたかと残った多義語を採点する評価ケースを足し、`claude plugin eval`(Claude Code の、実際にモデルを動かしてスキルの挙動を採点するコマンド)で実行する必要がある。これは後続の作業とする。評価の実行は課金されるモデル呼び出しを伴う。
