第 2 部

harness/ の内容

4 種類のファイルが、読み込まれる時点で分かれる

種類 読み込まれるとき ここでの用途
CLAUDE.md毎セッション作業の取り決め
ルール（4本）毎セッション伝え方、安全、委任の習慣と、従う標準の指定
サブエージェント（1本）委任されたとき独立性が必要な作業を、メインの会話から切り離す
プラグイン（1本）インストール後、毎セッションターンの終わりに文章をレビューするフック

ルール 4 本は、常に読み込まれる習慣を定める

communication.md
答えを先に書き、根拠をその下に置く。
delegation.md
サブエージェントに任せる場面と、依頼の書き方。
safety.md
事前に承認が必要な操作と、秘密情報の扱い。
standards.md
プロジェクトが決めていない場合に従う、確立された標準。
サブエージェントは 1 本

independent-reviewer は、作成者の推論を見ずにファイルだけからレビューします。使えるツールは Read、Grep、Glob に限られます。

インストールは 3 つの手順で終わる

  • ステップ 1 リポジトリを取得する

    git clone で手元に置く。

  • ステップ 2 インストールする

    bash install.sh が 3 つのパスを置き換える。

  • ステップ 3 読み込みを確かめる

    新しいセッションで /context を実行する。

git clone git@github.com:superluminal-jp/my-claude-code.git
cd my-claude-code
bash install.sh

設計の方針は、読み込む量を小さく保つこと

方針

標準は名前を挙げる

PEP 8 や Conventional Commits の中身を書き写さず、どの標準を使うかだけを書く。

上限

常時読み込みは 16,000 バイト以内

毎セッション読み込まれる文は、どのセッションでもコンテキストを使う。検査が上限を確かめる。

追加の条件

同じ誤りを 2 回見たら足す

具体的な指示は、どの標準にも書かれていないことと、繰り返した誤りに限る。

意図的に含めていないもの

  • settings.json：/config か直接の編集で管理する。
  • スキル：以前の手順は、いまは rules/standards.md の 1 行になっている。
  • Spec Kit と AI-DLC：使うプロジェクトごとに導入する。
  • 強制：ルールは指針であり、保証ではない。守らせたいことは権限設定かフックに置く。
