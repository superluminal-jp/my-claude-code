# presentation

デジタル庁デザインシステム（DADS）の HTML コンポーネントを使って、説明資料を 2 つの形式で作るための土台と、このリポジトリを題材にした試作です。`create-presentation` スキルを、このリポジトリ自身に使った結果に当たります。

- **スライド形式**: 16:9 の固定画面を 1 枚ずつ表示し、1 枚が PDF の 1 ページになります。
- **ページ形式**: 1 段組みで縦にスクロールして読みます。

`install.sh` はこのディレクトリをコピーしません。`harness/` とは独立しています。

## 使い方

```sh
bash presentation/setup.sh
```

`setup.sh` は、DADS の [コードスニペット（HTML版）](https://github.com/digital-go-jp/design-system-example-components-html) を、このディレクトリの隣の `design-system-example-components-html/` にクローンします。取得する版はタグ `v20261118` に固定しています。クローンしたディレクトリは `.gitignore` で除外しているので、使う版の記録は `setup.sh` の `DADS_TAG` だけです。

クローンの後、次のファイルをブラウザで直接開きます。サーバーもビルドも不要です。

| ファイル | 形式 |
|---|---|
| `my-claude-code-slides.html` | スライド形式の試作（11 枚） |
| `my-claude-code-page.html` | ページ形式の試作 |

スライド形式の操作は次のとおりです。

- 次へ: `→` `↓` `PageDown` `Space`
- 前へ: `←` `↑` `PageUp`
- 最初と最後: `Home` `End`
- PDF: ブラウザの印刷で「背景のグラフィック」を有効にして保存する

HTML は、DADS のサンプルと同じく Google Fonts から Noto Sans JP を読み込みます。外部に接続しない場合は、`<head>` の該当する 3 行を削除してください。文字はシステムのフォントで表示されます。

## 別のプロジェクトで使う

`bash install.sh` でハーネスをインストールし、そのプロジェクトで Claude に資料の作成を頼みます。`create-presentation` スキルが、土台と `setup.sh` をそのプロジェクトの `presentation/` にコピーし、ひな形から資料を書き、ブラウザで検査します。

`base/` と `setup.sh` の正本は、スキルの `assets/`（`harness/skills/create-presentation/assets/`）です。ここにあるのはそのコピーなので、変更はスキルの側で行います。

## 構成

| ファイル | 役割 |
|---|---|
| `setup.sh` | DADS を固定したタグで取得する |
| `base/deck.css` | 2 形式に共通の、DADS にない要素（段組み、パネル、コードブロック、樹形図、縦の間隔） |
| `base/slide.css` | スライド形式の土台（固定画面、レイアウト、印刷） |
| `base/slide.js` | スライド形式のキー操作。なくてもスクロールと印刷はできる |
| `base/page.css` | ページ形式の土台（本文の幅、節の間隔、印刷） |

### 決めごと

- **DADS のファイルは編集しません。** 足りない要素は `base/` に置き、色は DADS のトークン（`global.css` の CSS カスタムプロパティ）を使います。
- **寸法は `rem` で書きます。** DADS のコンポーネントは `rem` で寸法を決めています。`slide.css` はルートの文字サイズを「画面の幅 ÷ 1280 × 24px」にするので、コンポーネントは Web での 1.5 倍の大きさで表示され、ウィンドウの大きさに合わせて拡大・縮小します。`px` で書いた寸法はこの拡大に従いません。
- **スライドの見出しは `data-size="28"`、表は `data-size="dense"`、ステップナビゲーションは `data-size="small"` を使います。** 1.5 倍に拡大した状態で 1 枚に収めるためです。
- **スライドには、操作しないと読めない内容を置きません。** アコーディオンやタブは印刷で内容が欠けるので、ページ形式だけで使います。

### スライドのレイアウト

`<section class="slide">` が 1 枚です。`data-layout` で種類を選びます。

| `data-layout` | 用途 |
|---|---|
| `cover` | 表紙 |
| `section` | 章の扉 |
| `statement` | 覚えてほしい 1 文 |
| （指定なし） | 見出しと本文。本文は `<div class="slide__body">` に置く |

本文の組み方は、試作の HTML にコメント（`<!-- Pattern: ... -->`）で示しています。番号付きリスト、表、樹形図（縦）、樹形図（横）、2 段組み、手順とコード、3 つのパネル、リストの 8 種類です。

### 樹形図

階層を、入れ子のリストで書きます。`data-orientation` で向きを選びます。

| `data-orientation` | 向き |
|---|---|
| `vertical` | 根を上に置き、階層を下へ並べる |
| `horizontal` | 根を左に置き、階層を右へ並べる |

```html
<div class="deck-tree" data-orientation="vertical">
  <ul>
    <li><span class="deck-tree__node">根</span>
      <ul>
        <li><span class="deck-tree__node">子 1</span></li>
        <li><span class="deck-tree__node">子 2</span></li>
      </ul>
    </li>
  </ul>
</div>
```

- 最も外側の `<ul>` には、根の `<li>` を 1 つだけ置きます。
- 末端の項目が横に多いときは `vertical` が幅を使い切るので、`horizontal` を使います。試作のスライドでは、`vertical` は末端 6 個、`horizontal` は末端 6 個で 1 枚に収まっています。
- 入れ物より幅が広い樹形図は、その中で横にスクロールします。スライドでは、スクロールが要らない大きさに収めてください。

## 確認したこと

2026-11-25 に、Chromium で次を確認しました。はみ出しと樹形図の検査は、スキルの `scripts/check.cjs` で再実行できます。ブラウザが必要なので、`tests/run.sh` と CI には含めていません。

- スライド 11 枚のすべてで、内容が画面からはみ出さない（ウィンドウが 1280×720、1920×1080、1000×900 の場合）。
- キー操作で前後の 1 枚に移動し、URL の `#番号` が更新される。
- PDF に出力すると 11 ページになる。
- 樹形図は、スライドでは縦にも横にもスクロールせずに全体が表示される。ページ形式の幅 390px では、樹形図の中だけが横にスクロールする。
- ページ形式は、幅 390px で横スクロールが発生しない。

内容を増やしてスライドからはみ出した分は、表示されません（`overflow: hidden`）。1 枚の内容を変えたときは、画面で確かめてください。
