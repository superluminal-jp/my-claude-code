# 構成図: 市立図書館の蔵書予約システム(作例)

この一式は、架空の「蔵書予約システム」を4枚の図で説明する作例です。上から順に読むと、だれが使うか、何でできているか、予約のときに何が起きるか、どこで動いているかが分かります。技術者でない方は、1 のシステムコンテキスト図だけで全体を掴めるように書いています。

| # | 図 | 答える問い | 読み手 | 抽象度 |
|---|---|---|---|---|
| 1 | [システムコンテキスト図](01-system-context.md) | だれがこのシステムを使い、どの外部システムに頼っているか | 全員 | C4 system context |
| 2 | [コンテナ図](02-containers.md) | システムは何でできていて、部品どうしがどうやりとりするか | 開発者、運用者 | C4 container |
| 3 | [動的図: 本を予約する](03-dynamic-reservation.md) | 利用者が本を予約するとき、どの順で何が起きるか | 開発者、運用者 | C4 dynamic |
| 4 | [デプロイ図: 本番環境](04-deployment.md) | 本番環境で、どの部品がどこで動いているか | 運用者、基盤担当 | C4 deployment |

## 描かなかった図

- コンポーネント図: どのコンテナの内部についても問いがないため描いていません。API の内部を説明する必要が出たら、API だけを対象に1枚描きます。
- コード: 手では描きません。必要になったら、コードからツールで生成します。
