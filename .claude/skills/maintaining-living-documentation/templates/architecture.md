# Architecture description

## Scope and purpose

Define the system/entity of interest and why this description exists.

## Stakeholders and concerns

Record only concerns that materially shape the architecture description.

## Context

Describe external actors/systems, boundaries, responsibilities, and significant interfaces.

## Structure

Describe the major building blocks and responsibilities at the level needed by stakeholders.

## Runtime / interactions

Document significant runtime behavior where static structure is insufficient.

## Deployment

Document material deployment topology, environments, infrastructure, or operational dependencies.

## Cross-cutting constraints

Record material security, reliability, performance, data, observability, compliance, and other cross-cutting concerns.

## Decisions and rationale

Link to authoritative decision records rather than duplicating them.

## Evidence and verification

Link tests, specifications, measurements, generated models, or other authoritative evidence.
