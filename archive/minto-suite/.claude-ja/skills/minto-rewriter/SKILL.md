# Executive Structure Rewriter（エグゼクティブ構造リライター）

## Purpose（目的）

既存の文書や十分な内容を持つ下書きを、完全ですぐに使える最終文書へと変換する。

厳密な構造原則を、与えられた範囲全体にわたって内部的に適用する。分析の枠組み、内部的なラベル、レビューの過程を出力に露出させない。

## Use this skill when（このスキルを使う場面）

ユーザーが以下のような既存のものを提供した場合にこのスキルを使う。

- 下書き文書
- レポート
- メモ
- 提案書
- 記事
- 論文の一節
- エグゼクティブサマリー
- スライドのナラティブ（語りの筋）
- 書くための実質的な内容を十分に含む詳細なアウトライン

典型的な依頼には次のようなものがある。

- これを書き直してほしい
- この文書を改善してほしい
- 論の構成を立て直してほしい
- これをエグゼクティブ向けに仕上げてほしい
- この下書きを最終版にしてほしい
- 論理をもっと明確にしてほしい
- 洗練された版を作ってほしい
- 文書を簡潔で、説得力があり、意思決定志向のものにしてほしい

## Do not use this skill when（このスキルを使わない場面）

ユーザーの主な依頼が以下である場合は、このスキルを使わないこと。

- 現在の構造を診断する
- 構造上の問題を説明する
- スコアや評価を受け取る
- 対話を通じて論を共同で発見する
- トピックだけで実質的な素材がない状態から文書を作成する
- 他の変更済み成果物をそのまま反映するだけの、純粋に機械的な一行の契約同期を行う

## Compound requests（複合的な依頼）

実質的な文書更新が、独立して合致する他の作業と併せて発生する場合でも、このスキルは最終的な文書変換フェーズを引き続き担当する。前提となる診断作業やソース変更作業の出力を入力として用い、独立して適用可能などのドメイン制約も保持したうえで、事実面の契約が安定した時点の完成文書を返すこと。実質的な再構成を必要としない機械的な一行の同期は、引き続きこのスキルの対象外である。

## Output contract（出力契約）

完成した文書を主たる出力として返す。

明示的に求められない限り、以下を含めないこと。

- 枠組みの名称
- 専門的な構造用語
- ノードID
- ステータスラベル
- 分析テーブル
- 欠陥リスト
- リライトの過程についての説明
- 変更前後の比較
- ディスポジションマップ（対応表）
- 文書に先立つ別立てのアウトライン
- なぜその構造がうまくいくのかについてのメタ的な解説

読み手には、この結果が名の知れた枠組みから生成された文書としてではなく、自然に構成の整った文書として体験されるべきである。

## Full-application requirement（全面適用の要件）

局所的な編集だけで済ませないこと。

与えられた範囲全体を、以下を満たすように再構築する。

- 冒頭は、文書の目的に必要な文脈のみを提示する
- 主たる答え、推奨事項、あるいは中心となる論点が明示されている
- 各セクションが文書の中心目的を直接支えている
- 見出しは、適切な場合には有用な結論を述べている
- 関連する論点はまとめてグルーピングされている
- 異なる論理の種類が混在していない
- 各グループが一貫した順序に従っている
- 重要な重複や欠落が解消されている
- 根拠は、それが支える主張のすぐそばに置かれている
- アクション、理由、所見、リスク、事例が明確に区別されている
- 移行部分によって論の筋を追いやすくなっている
- 結びが、意思決定、含意、あるいは次のアクションを締めくくっている

ソースは構造上の制約ではなく、素材として扱うこと。

以下を行ってよい。

- 書き直す
- 順序を入れ替える
- 統合する
- 分割する
- 位置を移す
- 圧縮する
- 裏付けのある含意のみを用いて拡張する
- 冗長または無関係な内容を削除する
- ラベルを情報量のある見出しに変える
- ソースが支持しない場合には中心的な結論を変更する

変更を最小限に抑えるためだけに、元の階層、文言、結論、順序を維持しないこと。

## Factual integrity（事実の整合性）

以下を創作しないこと。

- 事実
- 根拠
- 引用
- 数値指標
- 日付
- 出典
- ステークホルダーの立場
- 因果関係の主張
- コミットメント

構造上必要な記述が裏付けを欠く場合、最も混乱の少ない有効な対処を選ぶこと。

1. ソースが裏付ける範囲まで主張を狭める
2. 限界をはっきりと述べる
3. 文書が明示的に作業中の下書きである場合は、目に見える形のプレースホルダーを用いる
4. 誤解を招かない場合は、裏付けのない主張を省く
5. 欠落した情報が有効な最終文書の作成を妨げる場合に限り、一度にまとめて一つの確認質問をする

ユーザーが作業中の下書きを求めていない限り、公開準備の整った文書に内部的なプレースホルダーを挿入しないこと。

## Rewrite workflow（リライトのワークフロー）

### 1. Establish the writing contract（執筆契約を定める）

以下を推定または特定する。

- 読み手
- 目的
- 文書の種類
- 望まれる意思決定または反応
- トーン
- 分量
- 必要なセクション
- 事実面の境界
- 提供される文脈

一つの欠けている決定事項が文書を大きく左右する場合は、簡潔にまとめた一つの質問をすること。それ以外は、明確に裏付け可能な仮定のもとで進めること。

### 2. Extract the source substance（ソースの内容を抽出する）

以下を分離する。

- 中心的な主張
- それを支える主張
- 根拠
- 文脈
- リスク
- アクション
- 事例
- 制約
- 未解決の論点

これは内部的に行うこと。求められない限り、抽出結果を出力しないこと。

### 3. Determine the document's controlling point（文書の中心的な論点を定める）

ソースによって裏付けられ、かつ読み手にふさわしい、最も強力な中心的論点を選ぶ。

ソースに競合する結論が含まれる場合は、ユーザーが述べた目的に最もよく合致するものを選ぶこと。その選択が本当に作業の妨げとなる場合は、一つの決定を求めること。

### 4. Rebuild the opening（冒頭を再構築する）

以下を満たす冒頭を作成する。

- 関連する共有された文脈から始める
- 文書が今重要である理由を提示する
- 意思決定事項や論点を特定する
- 文書の中心的な答えを早い段階で述べる

これを文書の種類に応じて調整すること。媒体が直接的な冒頭を求める場合に、型どおりの導入を無理に用いないこと。

### 5. Rebuild the body（本文を再構築する）

完全な階層構造を組み立てる。

各セクションについて。

- 一つの主要な論点を述べる
- その論点を支える素材のみを含める
- 比較可能な項目をまとめてグルーピングする
- 一つの順序付けの原則を用いる
- 根拠を、それが支える主張の近くに置く
- 分析とアクションを分離する
- 含意を明示する

### 6. Rebuild the ending（結びを再構築する）

文書にふさわしい形で締めくくる。

- 推奨事項
- 意思決定の要請
- 含意
- アクションプラン
- 結論
- 次のステップ

文書がすでに決定的に締めくくられている場合は、一般的な要約を付け加えないこと。

### 7. Edit and proof（編集と校正）

以下を確認する。

- 事実面の忠実さ
- 内部的な一貫性
- 用語の一貫性
- 読み手に見合った深さ
- 段落の焦点の絞り込み
- 能動態
- 不要な繰り返し
- 裏付けのない断定
- 書式
- 文法と句読点

### 8. Return only the finished artifact（完成した成果物のみを返す）

実質的な最終的な文章はすべて、適切な完成版の出力形式に収めること。

重大な限界、未解決の事実面の欠落、あるいは仮定を開示する必要がある場合に限り、文書の外側に短い注記を加えること。

## Format rules（形式のルール）

想定される表面形式を維持または適応させる。

- メールはメールのままとする
- メモはメモのままとする
- レポートはレポートのままとする
- スライドのナラティブはスライドのタイトルと補足内容のままとする
- 学術的な文章は適切な限定表現を保ったままとする
- エグゼクティブ向けの文章は意思決定や含意から書き始める

すべての成果物を汎用的なレポートに変換しないこと。

## User-facing language（読み手に向けた言葉遣い）

ユーザーが構造分析を明示的に求めない限り、以下の用語を使わないこと。

- SCQA
- Governing Question（統率的な問い）
- Governing Thought（統率的な考え）
- vertical logic（垂直方向の論理）
- horizontal logic（水平方向の論理）
- deductive grouping（演繹的なグルーピング）
- inductive grouping（帰納的なグルーピング）
- MECE
- pyramid（ピラミッド）
- node（ノード）
- structural status labels（構造上のステータスラベル）

通常のドメインにふさわしい言葉遣いを用いること。

## Quality guardrails（品質を守るためのガードレール）

- アウトラインやパッチのリストではなく、完成した文書を返すこと。
- 構造原則を、与えられた範囲全体にわたって適用すること。
- 内部的な推論や枠組みの用語を露出させないこと。
- 事実や根拠を創作しないこと。
- 文体上の都合で裏付けのない主張を残さないこと。
- 完成文書の前に分析を含めないこと。
- ASCIIアート、罫線文字、テキストによる図、文字ベースのツリー接続記号を使わないこと。
- 通常の見出し、段落、リストを用い、文書にふさわしい場合に限り表を用いること。
