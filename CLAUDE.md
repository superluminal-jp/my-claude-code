# About this repository

This repository keeps the author's Claude Code user-level configuration under Git. The source is `harness/`; `bash install.sh` copies its three managed paths (`CLAUDE.md`, `rules/`, `agents/`) into `~/.claude/`, replacing each so that it matches. `settings.json` and `skills/` are not managed here.

- Files under `harness/` apply in every project once installed. Keep them universal: no facts about this repository, and nothing that duplicates a per-project workflow (Spec Kit and AI-DLC are set up in each project, not here).
- This file is for developing this repository only. It is not installed.
- Change `harness/` and run `bash install.sh`; do not edit `~/.claude/` directly. A session here runs on the installed copy, so an edit takes effect after the next install and a new session. Inside the Bash sandbox `install.sh` cannot write to `~/.claude/`, so it needs the person's approval to run outside it.
- Run `bash tests/run.sh` before committing. It checks the format of `harness/`, the two plugins, and the installer, and writes only under `$TMPDIR`.
- `harness/plugins/` holds two Claude Code plugins, `writing-check` and `dads-presentation`, listed in `.claude-plugin/marketplace.json`. It is the one part of `harness/` that `install.sh` does not copy, because `~/.claude/plugins/` belongs to Claude Code; each plugin is installed at user scope with `claude plugin marketplace add` and `claude plugin install`, and Claude Code reads it in place from this checkout.
- The Stop hook of `writing-check` judges text against the installed `rules/communication.md`, `rules/standards.md`, and `rules/safety.md`, so the criteria are changed there; the hook's prompt says which of their requirements can be judged from text, and adds only the criteria for language that no rule states. When a rule is added, renamed, or gains a requirement that shows in the text, update the prompt in `harness/plugins/writing-check/hooks/hooks.json`, and `harness/plugins/writing-check/reminder.md`, which the plugin's UserPromptSubmit hook puts before Claude with every prompt and which lists the same requirements in short.
- Front matter uses only the fields Claude Code reads.
- The one skill is `create-presentation`, in the `dads-presentation` plugin. Add a skill only for a procedure that no named standard covers, and put it in a plugin (`harness/plugins/<plugin>/skills/<name>/SKILL.md`), so that `install.sh` leaves `~/.claude/skills/` alone; `tests/check_harness.py` checks it there.
- The assets of `create-presentation` are the source of `presentation/base/` and `presentation/setup.sh`. Change them in the skill, copy them to `presentation/`, and run `node harness/plugins/dads-presentation/skills/create-presentation/scripts/check.cjs` on the templates and on the files in `presentation/`; it needs the DADS clone that `bash presentation/setup.sh` makes, and a browser, so `tests/run.sh` does not run it.
- Name the established standard instead of restating its contents, and add a specific instruction only for what no standard covers or for a mistake seen twice.
- Every always-loaded line costs context in every session. Before adding to `harness/CLAUDE.md` or to a rule without `paths`, consider a path-scoped rule.
- Keep `README.md` and `README.ja.md` in step with each other and with the contents of `harness/`.
