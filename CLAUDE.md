# About this repository

This repository keeps the author's Claude Code user-level configuration under Git. The source is `harness/`; `bash install.sh` copies its four managed paths (`CLAUDE.md`, `rules/`, `agents/`, `skills/`) into `~/.claude/`, replacing each so that it matches. `settings.json` is not managed here.

- Files under `harness/` apply in every project once installed. Keep them universal: no facts about this repository, and nothing that duplicates a per-project workflow (Spec Kit and AI-DLC are set up in each project, not here).
- This file is for developing this repository only. It is not installed.
- Change `harness/` and run `bash install.sh`; do not edit `~/.claude/` directly. A session here runs on the installed copy, so an edit takes effect after the next install and a new session. Inside the Bash sandbox `install.sh` cannot write to `~/.claude/`, so it needs the person's approval to run outside it.
- Run `bash tests/run.sh` before committing. It checks the format of `harness/`, the `writing-check` plugin, the `create-presentation` skill, and the installer, and writes only under `$TMPDIR`.
- `harness/plugins/writing-check/` is a Claude Code plugin, listed in `.claude-plugin/marketplace.json`. It is the one part of `harness/` that `install.sh` does not copy, because `~/.claude/plugins/` belongs to Claude Code; it is installed at user scope with `claude plugin marketplace add` and `claude plugin install`, and Claude Code reads it in place from this checkout. Use a plugin only for hooks, which would otherwise go in `settings.json`; skills and subagents are copied by `install.sh`, and rules and `CLAUDE.md` cannot be carried by a plugin.
- `harness/plugins/writing-check/reminder.md`, which the plugin's UserPromptSubmit hook puts before Claude with every prompt, lists in short the requirements of the installed `rules/communication.md`, `rules/standards.md`, and `rules/safety.md` that show in the text, so the criteria are changed in those rules; it adds only the criteria for language that no rule states. When a rule is added, renamed, or gains a requirement that shows in the text, update `reminder.md`.
- Front matter uses only the fields Claude Code reads.
- The one skill is `create-presentation`. Add a skill only for a procedure that no named standard covers, as `harness/skills/<name>/SKILL.md`; `tests/check_harness.py` checks it. `install.sh` replaces `~/.claude/skills/` as a whole, so every user-level skill lives here.
- `harness/skills/create-presentation/assets/base/` is the source of `presentation/base/`: change it in the skill and copy it. `assets/dads/` is a copy of one DADS release written by `bash scripts/vendor-dads.sh <tag>`; do not edit it by hand, since `tests/run.sh` checks it against its `SHA256SUMS`. After either change, run the skill's `scripts/copy-dads.sh presentation` and `node harness/skills/create-presentation/scripts/check.cjs` on the templates and on the files in `presentation/`; the check needs a browser, so `tests/run.sh` does not run it.
- Name the established standard instead of restating its contents, and add a specific instruction only for what no standard covers or for a mistake seen twice.
- Every always-loaded line costs context in every session. Before adding to `harness/CLAUDE.md` or to a rule without `paths`, consider a path-scoped rule.
- Keep `README.md` and `README.ja.md` in step with each other and with the contents of `harness/`.
